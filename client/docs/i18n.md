# 前端国际化（i18n）开发约定

> 本页面是前端多语言开发的唯一参考，开发新页面/新功能时按此约定执行。

## 1. 技术栈与架构

- 依赖：`i18next` + `react-i18next`，配合 `antd` 官方 locale。
- 初始化入口：`client/src/i18n/index.ts`
- 语言资源：`client/src/i18n/locales/zh.json`（中文）、`en.json`（英文）
- 当前支持 2 种语言：`zh`（默认）、`en`。

### 初始化逻辑（index.ts）

```ts
const savedLang = localStorage.getItem('lang') || 'zh';

i18n.use(initReactI18next).init({
  resources: {
    zh: { translation: zh },
    en: { translation: en },
  },
  lng: savedLang,          // 从 localStorage 恢复上次语言
  fallbackLng: 'zh',       // 缺失 key / 缺失语言时回退中文
  interpolation: { escapeValue: false }, // React 已转义，无需再转义
});
```

要点：

- `fallbackLng: 'zh'`：**en.json 漏写的 key 会自动显示中文**，不报错但属于缺陷，合代码前必须补全。
- 首次进入默认中文；用户切换后语言写入 `localStorage.lang`。

## 2. 文件与目录

```
client/src/i18n/
├── index.ts          # i18next 初始化（勿改，除非调整语言列表）
└── locales/
    ├── zh.json       # 中文文案（基准，key 的权威来源）
    └── en.json       # 英文文案（key 结构必须与 zh.json 一致）
```

## 3. 语言切换

切换入口在 `client/src/layouts/HeaderTools.tsx`：

```ts
const currentLang = i18n.language;
const toggleLanguage = () => {
  const nextLang = currentLang === 'zh' ? 'en' : 'zh';
  i18n.changeLanguage(nextLang);
};
```

`main.tsx` 监听 `languageChanged` 事件，同步 `antd` 组件库的 locale（日期、分页、弹窗按钮等）并持久化：

```ts
const handleLangChange = (lng: string) => {
  setAntdLocale(lng === 'en' ? enUS : zhCN);
  localStorage.setItem('lang', lng);
};
i18n.on('languageChanged', handleLangChange);
```

> 因此切换语言时，业务文案（t()）与 antd 内置文案会同时生效，无需额外处理。

## 4. 组件内使用（React 组件）

统一使用 `useTranslation`：

```tsx
import { useTranslation } from 'react-i18next';

export default function MyPage() {
  const { t } = useTranslation();

  return <Button>{t('common.save')}</Button>;
}
```

### 带插值的用法

```tsx
// zh.json: "customerPendingTip": "客户「{{name}}」尚未建档"
// 用法：
t('lead.customerPendingTip', { name: editing.companyName })
```

```tsx
// zh.json: "batchDeleteConfirm": "确定删除选中的 {{n}} 条线索？"
message.confirm({
  title: t('lead.batchDeleteConfirm', { n: selectedRowKeys.length }),
});
```

插值变量命名建议：短且语义化（`count`、`n`、`name`）。**中英文两边的 `{{变量}}` 必须一致**，否则英文下会显示原始占位符。

## 5. 非组件场景使用（工具函数 / API 层）

组件外（如 `client/src/api/request.ts`）无法用 hook，直接引入 i18n 单例：

```ts
import i18n from '../i18n';

// request.ts 示例
if (error.response?.status === 429) {
  getMessage().error(i18n.t('error.tooManyRequests'));
}
const msg = error.response?.data?.message || i18n.t('error.networkError');
```

> 注意：`i18n.t()` 不会触发组件重渲染，因此只用于组件外的提示/兜底文案；组件内一律用 `useTranslation`。

## 6. JSON 文案结构规范

### 6.1 顶级命名空间按「模块/页面」划分

当前已有命名空间（按业务域归类，沿用即可）：

| 命名空间 | 用途 |
| --- | --- |
| `common` | 全局通用：按钮、状态、通用提示 |
| `login` / `dashboard` / `menu` / `header` | 框架层 |
| `user` / `role` / `dept` / `perm` | 系统管理 |
| `product` / `taxonomy` | 产品 |
| `sales` / `lead` / `channel` / `customerType` | 销售域 |
| `currency` / `error` | 全局基础 |

新增业务模块时，按页面/功能新建顶级命名空间（如 `quote`、`sample`、`order`），不要塞进 `common`。

### 6.2 key 命名规范

- 全部使用 **camelCase**：`nameRequired`、`searchPlaceholder`。
- 常用语义后缀（保持全局一致）：

| 后缀 | 含义 | 示例 |
| --- | --- | --- |
| `Title` / `Placeholder` / `Required` | 标题 / 占位 / 校验必填 | `createTitle`、`namePlaceholder`、`nameRequired` |
| `Success` / `Failed` | 操作结果提示 | `createSuccess`、`saveFailed` |
| `Confirm` / `Hint` / `Tip` | 确认 / 提示 | `deleteConfirm`、`comboEditHint` |
| `Add` / `Edit` / `Detail` | 动作 | `addTitle`、`editTitle` |
| `Status` + 状态值 | 枚举值：`statusNew`、`statusContacted` | `status` 下的枚举统一加前缀 |

- 动词短语直接用语义词：`search`、`refresh`、`save`、`cancel`。

### 6.3 zh.json 是基准，en.json 必须同构

- 中英文 **key 树结构必须完全一致**（新增/删除/重命名 key 要两边同步改）。
- 每个 key 的键名固定，仅 value 翻译。
- 合并代码前自查：`en.json` 是否有漏 key（可用脚本比对，或至少对照模块检查）。

## 7. 新增功能时的完整步骤（Checklist）

以「新增 `quote`（报价）页面」为例：

1. 在 `zh.json` 新增顶级命名空间 `"quote": { ... }`，按 6.2 规范命名 key。
2. 在 `en.json` 对应位置新增**结构一致**的 `"quote": { ... }` 英文翻译。
3. 组件中使用：
   ```tsx
   const { t } = useTranslation();
   <h2>{t('quote.title')}</h2>
   <Input placeholder={t('quote.namePlaceholder')} />
   ```
4. 表单校验错误信息用 `t()` 返回，不要硬编码：
   ```tsx
   rules={[{ required: true, message: t('quote.nameRequired') }]}
   ```
5. 接口错误提示走 `api/request.ts` 的兜底文案；业务侧如有自定义提示，用 `i18n.t()`。
6. 检查：把语言切到 `en`，逐个走一遍新页面，确认无中文残留、无 `{{xxx}}` 原样输出。
7. 确认无误后提交（注意：**不要硬编码任何中文/英文文案**）。

## 8. 注意事项 / 反模式

| 场景 | 正确做法 | 错误做法 |
| --- | --- | --- |
| 组件内文案 | `t('xxx')` | 直接写中文/英文字符串 |
| 组件外兜底文案 | `i18n.t('xxx')` | 直接写字符串 |
| 动态拼接（如「共 N 条」） | 用插值 `t('common.total', { count: n })` | `\`共 ${n} 条\`` |
| 枚举显示（状态、来源等） | key 按 `status + 值` 命名 | 组件内 switch 返回字符串 |
| `en.json` 翻译 | 与 `zh.json` 同构，同步维护 | 只改中文，英文缺失 |

其他约定：

- **中文优先**：新功能先写 `zh.json`，再补 `en.json`。
- **不要用 `t` 包裹纯变量**：`t(column)` 这种动态 key 无法被检查且易出错；枚举/选项值通过映射表维护。
- **key 尽量短**：`page.模块.语义`，避免超长路径。
- 后端返回的枚举/字典值（如国家、币种）保持原值，不做翻译（可走 `currency` 命名空间的参考方式，见 `HeaderTools` 的币种展示）。
- 时间、数字格式化保持项目现状，暂未引入 `i18next` 的复数/日期插件；需要格式化展示用 `dayjs`/原生 API。
