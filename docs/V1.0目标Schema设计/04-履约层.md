# 04 · L3 履约层（13 张表）

> 履约层 = `SampleOrder → SalesOrder → ProductionOrder → QC → Shipment → Payment → Profit`，**不含任何销售阶段**。
> 本层是审计 `P0-2`（`Order` 五合一）的拆解落点，补齐主链缺口「QC」，并解决 `P1-4`（采购与订单无关联导致利润不可信）。
> 上游依赖：`01`（User / NumberSequence / Attachment / **Currency**）、`02`（Product / Supplier）、`03`（Customer / Opportunity / Quotation / CustomerProduct）。
>
> **draft2 修订（本层）**
> 1. **Q14 / 第三批**：`QualityInspection` **删除 `salesOrderId`**，宿主仅 `productionOrderId` / `shipmentId`，DB CHECK 升级为 **exact-one（二选一）**（见 §5.1）；删除 `SalesOrder.inspections`；
> 2. **Q10 / 第三批**：来源打样单改为 `SalesOrder.sampleOrderId String?` **单向持有**（**去掉 `@unique`**，`SampleOrder` **1:N** `SalesOrder`），删除 `SampleOrder.salesOrderId` 与 `SalesOrder.sampleOrders[]`；
> 3. **Q15**：`SalesOrder.status = CONFIRMED` 时置 `Opportunity.outcome = WON`（见 `03` §4.3），本层只负责触发；
> 4. **ADR-20**：`Shipment` 新增运费三字段 `freightAmount / freightCurrency / freightAmountCny`，作为 `Profit.freightCostCny` 的**唯一数据源**；
> 5. **ADR-14**：`PurchaseOrderItem` 新增 `productionOrderItemId?`，打通 `SalesOrderItem → ProductionOrderItem → PurchaseOrderItem → PurchaseOrder` 成本归集链；
> 6. **Payment** 增加宿主 DB CHECK（**第三批升级为 exact-one：`salesOrderId` / `purchaseOrderId` 二选一**）；
> 7. **Q7/Q13**：全部金额 / 汇率 / 比率由 `Float` 改 `Decimal`（精度见 `00` §6.5）；数量改 `Decimal(18,4)`；
> 8. **Q9**：删除 `SampleOrder.deletedAt`；本层无任何软删除字段；
> 9. **relation 补齐**：`SalesOrderItem.productionItems / shipmentItems`、`SalesOrder.purchaseOrders`、`ProductionOrderItem.purchaseOrderItems`；删除 `SalesOrder.approvalRecords[]`；
> 10. 新增 `ProductionItemStatus` / `PurchaseItemStatus` / `PurchaseType` 三个枚举（Q1 状态枚举化）。
> 11. **第三批（销售-履约关系终修）**：QC / Payment 宿主 CHECK 升级为 **exact-one**；`SalesOrder.sampleOrderId` 去 `@unique`（`SampleOrder` 1:N `SalesOrder`）；`SalesOrder.quotationId` 明确可空语义；`SampleOrder` **不加 `quotationId`**（与报价保持间接关系）；`Payment` 明确 `IN/OUT` 宿主规则与 `customerId` 辅助语义；新增 §13 关系矩阵。

## 2. `SampleOrder` + `SampleRound`（打样）

```prisma
/// 打样单：由商机发起（也可独立发起，见总览 Q6）
model SampleOrder {
  id       String @id @default(cuid())
  sampleNo String @unique   // SM-yyyyMMdd-0001

  opportunityId String?
  opportunity   Opportunity? @relation(fields: [opportunityId], references: [id], onDelete: SetNull)
  customerId    String
  customer      Customer     @relation(fields: [customerId], references: [id], onDelete: Restrict)

  // ---------- 来源打样 → 订单 的关系（Q10 / 第三批终修）----------
  // 真实外键**唯一**在 SalesOrder 一侧（SalesOrder.sampleOrderId，**非 unique**），本侧仅反向 relation。
  // 基数：SampleOrder 1:N SalesOrder —— 一次打样可支撑客户后续多次下单。
  // 禁止再声明 `salesOrderId`（会造成双向真实 FK 与双写不一致）。
  salesOrders SalesOrder[] @relation("OrderSourceSample")

  // 与 Quotation 的关系：**不声明 `quotationId`**（第三批 §9 定案）。
  // SampleOrder 经 `opportunityId` 间接追溯来源报价；免费打样 / 老客重打 / 内部开发样 /
  // 直接样品需求都可能没有正式报价单，故**不要求** SampleOrder 必须来自 Quotation。

  productId   String?
  product     Product? @relation(fields: [productId], references: [id], onDelete: Restrict)

  productName String
  spec        String?
  craft       String?
  size        String?
  packaging   String?

  quantity    Int       @default(1)   // 意向打样数量（整数口径，见 §12#7）
  /// 打样要求（结构化）
  requirement String?
  /// 目标价：客户口头/文本目标（可能为区间，如 "0.80-0.95 USD"），
  /// 属**需求描述**而非结算金额，故保留 String（不得当金额参与计算）。
  targetPrice String?

  status SampleStatus @default(DRAFT)
  /// 当前轮次
  currentRound Int @default(1)
  rounds SampleRound[]

  /// 费用（打样费可回收）；币种见 feeCurrency
  feeAmount     Decimal? @db.Decimal(18, 4)
  feeCurrency   Currency @default(USD)
  feeRecoverable Boolean @default(false)

  customerSnapshot Json?
  ownerId String?
  notes   String?

  createdBy String?
  createdAt DateTime  @default(now())
  updatedBy String?
  updatedAt DateTime  @updatedAt
  // 注意：无 deletedAt —— 业务单据只允许 CANCELLED（Q9 / ADR-08）

  @@index([opportunityId])
  @@index([customerId])
  @@index([status])
  @@index([productId])
}

/// 打样轮次：一轮打样 = 设计 → 开模 → 寄样 → 反馈
model SampleRound {
  id            String @id @default(cuid())
  sampleOrderId String
  sampleOrder   SampleOrder @relation(fields: [sampleOrderId], references: [id], onDelete: Cascade)
  roundNo       Int    @default(1)

  designAt   DateTime?  // 设计完成
  moldAt     DateTime?  // 开模完成
  sentAt     DateTime?  // 寄样
  feedbackAt DateTime?  // 客户反馈
  /// 快递单号 / 寄送方式
  trackingNo String?
  /// 本轮费用（币种同 SampleOrder.feeCurrency）
  feeAmount  Decimal? @db.Decimal(18, 4)

  result     SampleRoundResult @default(PENDING)
  /// 客户反馈原文
  feedback   String?
  /// 本轮改进点（下一轮输入）
  improvements String?

  createdBy String?
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  @@unique([sampleOrderId, roundNo])
  @@index([sampleOrderId])
}
```

**为什么需要 `SampleRound`（ADR-12）**：旧模型用 `Order.stage`（单值 `DESIGN/MOLD/SAMPLE_SENT`）表达打样进度，导致 ① 第 2 轮打样无法记录（会覆盖第 1 轮）；② 无法统计「平均打几轮才通过」；③ 「设计完成」与「已寄样」不能同时为真（真实业务流程中第 1 轮已寄样、第 2 轮在设计，是并行的）。轮次表把「单值状态」改为「时间线」。

> **Q10 说明（第三批修正为 1:N）**：来源打样单关系为 `SalesOrder.sampleOrderId` **单向持有**：
> - **`SampleOrder` 1 : N `SalesOrder`** —— `sampleOrderId` **不加 `@unique`**（一次打样 → 客户后续多次下单）；
> - `SalesOrder.sampleOrderId` **可空**：无需打样的订单（老客复购 / 框架订单）置 `NULL`，**不强制**要求存在 `SampleOrder`；
> - `SalesOrder.sampleOrderId` 是全系统 **SampleOrder ↔ SalesOrder 唯一的真实 FK**（禁止在 `SampleOrder` 侧再加 `salesOrderId`）；
> - `SampleOrder` 删除时 `SalesOrder.sampleOrderId` 置 NULL（`onDelete: SetNull`），不销毁订单；
> - 迁移时**不得**保留旧的 `SampleOrder.salesOrderId` 列（`05` §4.4 有 ALTER 步骤）。
>
> **⚠ 与 `00` / `05` 的口径差异（本批不可改，须后续同步）**：`00` 关系表与 `05` §4.4 仍按 draft2 写成「`sampleOrderId? @unique`，最多 1 张」。第三批按业务要求定为 **1:N**，`00` / `05` 需在后续批次同步（本批禁止修改这两个文件）。

## 3. `SalesOrder` + `SalesOrderItem`（销售订单 —— 履约主载体）

### 3.1 相对旧 `Order`（`type=ORDER`）的字段去向

| 旧字段 | 新去向 | 说明 |
|---|---|---|
| `orderNo` | `SalesOrder.orderNo` | 保留 |
| `customerId` | `SalesOrder.customerId` | — |
| `pipelineId` | `SalesOrder.opportunityId` | 语义修正（`SalesPipeline` → `Opportunity`） |
| `status`（`DRAFT/SUBMITTED/APPROVED/REJECTED`） | `SalesOrder.status`（**新 10 态**） + `ApprovalRecord` | 旧 `status` 是**审批态**，与履约态混用（`P0-2`）；审批态迁入 `ApprovalRecord` |
| `stage`（`DESIGN/MOLD/SAMPLE_SENT`） | → `SampleRound.designAt/moldAt/sentAt` | 履约状态字段不再兼职打样 |
| `items`（JSON） | `SalesOrderItem[]` | P0-4 |
| `amountCNY` | `totalAmountCny` + `totalAmount` + `exchangeRate` | 单币种 → 三件套 |
| `orderDate/deliveryDate` | `DateTime?` | 字符串 → 日期类型 |
| `depositAmount/depositPaid` | `depositAmount` / `depositPaidAt` | 布尔 → 时间戳（可回答「何时付的」） |
| `paymentTerms` | 保留 | — |
| `productionStartDate` | `productionStartAt` | 旧字段**无任何写入路径**（审计确认），新设计由 `ProductionOrder` 触发写入 |
| `shippedDate` | `shippedAt` | 同上，由 `Shipment` 触发写入 |
| `sampleOrderDate/designDate/moldDate/sampleSentDate` | → `SampleOrder` / `SampleRound` | 打样相关字段离开订单 |
| `targetType/targetId`（`PRODUCT/GROUP` 多态） | **删除** | 改由 `SalesOrderItem.productId` 直接关联（总览原则 10） |
| `title` | **删除** | 订单标题由 `customerName + orderNo` 派生，无独立业务含义 |
| `createdBy` | 保留 | — |

> **draft2 删除项**：`receivedAmountCny`（改名 `paidAmountCny`，与 `00` §4.3 状态机口径统一）、`balancePaid`（布尔无法回答「何时付清」，与 `paidAmountCny >= totalAmountCny` 派生冲突 → 删除）、`sampleOrders[]`（Q10）、`inspections[]`（Q14）、`approvalRecords[]`（多态旁挂）。

### 3.2 履约状态推进的实现约定

状态**不允许前端直接写值**。后端提供显式动作接口，每个动作内部校验前置条件（见 `00` §4.3）并写时间戳 + `OperationLog`：

| 动作接口 | 触发状态迁移 |
|---|---|
| `POST /orders/:id/confirm` | `DRAFT → CONFIRMED`（**同时置 `Opportunity.outcome = WON`**，Q15） |
| `POST /orders/:id/request-deposit` | `CONFIRMED → DEPOSIT_PENDING` |
| `POST /orders/:id/payments`（创建收款并确认） | `DEPOSIT_PENDING → DEPOSIT_PAID` |
| `POST /orders/:id/production-orders`（创建工单） | `DEPOSIT_PAID → IN_PRODUCTION` |
| `POST /orders/:id/inspections`（创建质检并出结果） | `IN_PRODUCTION → QC → READY_TO_SHIP` |
| `POST /orders/:id/shipments`（创建出货单） | `READY_TO_SHIP → SHIPPED` |
| 系统自动（收款 + 出货均完结） | `SHIPPED → COMPLETED` |

> 这一条是解决 `P0-2` 的关键：**状态由事实驱动，不由人工点选**，从根上避免「订单已发货但状态还在生产中」。

### 3.3 `CONFIRMED → Opportunity.outcome = WON`（Q15）

```
SalesOrder.status 首次变为 CONFIRMED
        │
        ├── Opportunity.outcome = WON
        ├── Opportunity.wonAt    = now()
        └── Opportunity.outcomeAt = now()
```

| 不作为 WON 判定点的时点 | 原因 |
|---|---|
| `Quotation.status = ACCEPTED` | 客户接受报价 ≠ 最终下单 |
| 定金到账（`DEPOSIT_PAID`） | 属履约进度，不是销售结论 |
| 生产开始 / 出货 | 同上 |

> `outcome = WON` 后订单被 `CANCELLED` 时 **V1 不自动回滚**（由业务人工回到 `OPEN` 或置 `LOST`），详见 `03` §4.3。

### 5.1 宿主规则（Q14 / ADR-13 / 第三批定案）

**硬性规则：`QualityInspection` 的业务宿主只有 `ProductionOrder` 或 `Shipment`，且必须（也仅能）挂其中一个。**

| 场景 | `type` | 宿主（**二选一，恰好一个**） |
|---|---|---|
| 来料检 | `INCOMING` | `productionOrderId`（批次独立收货时可挂 `shipmentId`） |
| 生产过程检 | `IN_PRODUCTION` | `productionOrderId` |
| 生产终检 | `FINAL` | `productionOrderId` |
| **订单级出货前终检** | `PRE_SHIPMENT` | **`shipmentId`** |

**DB CHECK 约束（必须手写 SQL，Prisma schema 无法表达）**

```sql
-- 1) 质检宿主：exact-one（二选一），不允许「都 NULL」，也不允许「都有值」
ALTER TABLE "QualityInspection"
  ADD CONSTRAINT "quality_inspection_host_check"
  CHECK (
    ("productionOrderId" IS NOT NULL AND "shipmentId" IS NULL)
    OR
    ("productionOrderId" IS NULL AND "shipmentId" IS NOT NULL)
  );

-- 2) 收付款宿主：exact-one（二选一），见 §8
ALTER TABLE "Payment"
  ADD CONSTRAINT "payment_host_check"
  CHECK (
    ("salesOrderId" IS NOT NULL AND "purchaseOrderId" IS NULL)
    OR
    ("salesOrderId" IS NULL AND "purchaseOrderId" IS NOT NULL)
  );
```

> **Prisma 无法表达该约束**：跨字段 XOR（exact-one）既不是 `@unique` 也不是普通 FK 规则，**`schema.prisma` 写不出来**，必须在 migration 中手写 `CHECK`（`00` §4.3 的 QC 前置条件依赖它）。
> **配套 `onDelete`**：因宿主要求 exact-one，两个宿主关系均用 `onDelete: Restrict`。若用 `SetNull`，删除宿主会把该列置空 → 两个宿主同时为 NULL → 直接违反 CHECK（删除会被数据库以 `check_violation` 拒绝，报错含义不清）。`Restrict` 表达「QC 是历史证据，宿主不可被静默删除」。
> **实施提醒**：`prisma migrate dev` **不会**检测到 CHECK 约束差异，因此这两个约束一旦用 SQL 建好，就要在后续所有 migration 中保持不变；若被误删，`migrate diff` 不会提示，需靠人工核对。
> **为什么必须新增 QC**：目标主链明确包含 `ProductionOrder → QC → Shipment`，而当前 33 张表中**没有任何质检对象**。`Order.status` 也没有 QC 态。这导致「QC 未通过也能出货」在数据层完全无法阻止。
> **为什么删除 `salesOrderId`**：draft1 的三可空 FK 会产生「三空孤儿行」，且订单级质检可由生产单/出货单的 `salesOrderId` 间接得到。删除后 `SalesOrder` 侧也不再声明 `inspections[]`（`00` §4.3 的 `QC` 前置条件通过间接追溯判定）。


### 8.1 相对旧 `PaymentRecord` 的变更

| 项 | 旧 | 新 | 原因 |
|---|---|---|---|
| 方向 | 只能表示收款（`RECEIVED/PENDING`） | `direction: IN/OUT` | 采购付款无处记录，利润成本缺一半 |
| 关联 | `orderId`（必填，指向万能 `Order`） | `salesOrderId` / `purchaseOrderId`（**DB CHECK exact-one**） | 拆分后可同时挂收付款 |
| `customerId` | 必填（收款时冗余） | 可空（**辅助字段，非宿主**） | 付款给供应商时无客户；业务归属由宿主 FK 决定，一致性走应用层校验 |
| 币种 | 无 `currency`，只有 `amount(CNY)` | 三件套（`currency` + `exchangeRate` + `amount/amountCny`） | 外币收汇无法记录 |
| 金额类型 | `Float` | `Decimal(18,4)` | 精度（Q7） |
| `status` | `RECEIVED / PENDING` | `PENDING / RECEIVED / CONFIRMED / FAILED` | 「已到账」与「已对账确认」是两步 |
| `payDate` | `String?` | `DateTime?` | 字符串 → 日期类型 |
| 编号 | `paymentNo String?` | `paymentNo String @unique` | 补号 + 唯一（见 `05` §12） |
| 凭证 | 无 | `voucherRemark` + `Attachment` | 财务审计要求凭证留存 |

> **CHECK 语义（第三批定案）**：DB 层用 **exact-one** 保证「`Payment` 必须拥有且只能拥有一个业务宿主」；**方向与宿主的对应关系属应用层校验**：
>
> | `direction` | 含义 | 宿主要求（应用层） |
> |---|---|---|
> | `IN` | 公司**收到**客户款项 | `salesOrderId` 必须存在，`purchaseOrderId` 必须为空 |
> | `OUT` | 公司向供应商**付款** | `purchaseOrderId` 必须存在，`salesOrderId` 必须为空 |
>
> `customerId` 为辅助主体字段，**不参与**宿主判定。

## 9. `Profit`（利润核算）

```prisma
model Profit {
  id       String @id @default(cuid())
  profitNo String @unique   // PF-yyyyMMdd-0001

  salesOrderId String @unique
  salesOrder   SalesOrder @relation(fields: [salesOrderId], references: [id], onDelete: Restrict)

  revenueCny   Decimal  @db.Decimal(18, 4)

  materialCostCny  Decimal @default(0) @db.Decimal(18, 4)  // 原辅料 ← PurchaseOrder(purchaseType=MATERIAL)
  outsourceCostCny Decimal @default(0) @db.Decimal(18, 4)  // 外发加工 ← PurchaseOrder(purchaseType=OUTSOURCE)
  packagingCostCny Decimal @default(0) @db.Decimal(18, 4)  // 包材 ← PurchaseOrder(purchaseType=PACKAGING)
  laborCostCny     Decimal @default(0) @db.Decimal(18, 4)  // 内部人工（手工录入）
  freightCostCny   Decimal @default(0) @db.Decimal(18, 4)  // 运费 ← Σ Shipment.freightAmountCny（ADR-20）
  otherCostCny     Decimal @default(0) @db.Decimal(18, 4)  // 其他（手工录入）
  totalCostCny     Decimal @default(0) @db.Decimal(18, 4)  // 汇总

  // ---------- 结果 ----------
  profitCny Decimal @default(0) @db.Decimal(18, 4)   // = revenueCny - totalCostCny
  margin    Decimal @default(0) @db.Decimal(9, 4)    // 利润率 %（百分数语义）

  status ProfitStatus @default(DRAFT)
  /// 成本来源快照（记录各成本项的计算依据，便于复盘）
  costSnapshot Json?
  calculatedAt DateTime?

  remark    String?
  createdBy String?
  createdAt DateTime  @default(now())
  updatedBy String?
  updatedAt DateTime  @updatedAt

  @@index([status])
}
```

### 9.1 相对旧 `ProfitRecord` 的变更（对应 `P1-4`）

| 项 | 旧 | 新 | 原因 |
|---|---|---|---|
| 成本 | 单个 `cost Float?` 手工填写 | 6 项成本分类 + 汇总（全部 `Decimal`） | 无法回答「这单为什么亏」 |
| 成本来源 | 无关联 | 从 `PurchaseOrder` / `Shipment` 归集（`salesOrderId` 打通后） | ADR-14 |
| 与订单关系 | `orderId`（多对一，可建多条） | `salesOrderId @unique`（一单一条） | 一单多条利润单会导致统计重复；反向字段为 `SalesOrder.profit`（**单数**，与 unique FK 匹配） |
| `customerId` | 必填 | **删除** | 冗余（经 `salesOrder.customerId` 派生），并修正 `03` `Customer.profits` 反向 relation |
| 利润率 | `margin Float?` 可空 | 非空 `Decimal(9,4)`，自动计算 | 统一百分数语义（Q13） |
| 汇率 | 无 | 三件套 | 外币订单利润失真 |

**成本归集公式（定稿，供实施直接落地）**

```
materialCostCny  = Σ PurchaseOrder.totalAmountCny  where purchaseType = MATERIAL  AND salesOrderId = X
outsourceCostCny = Σ PurchaseOrder.totalAmountCny  where purchaseType = OUTSOURCE AND salesOrderId = X
packagingCostCny = Σ PurchaseOrder.totalAmountCny  where purchaseType = PACKAGING AND salesOrderId = X
freightCostCny   = Σ Shipment.freightAmountCny     where salesOrderId = X
laborCostCny     = 手工录入（V1 不做工时核算）
otherCostCny     = 手工录入
totalCostCny     = materialCostCny + outsourceCostCny + packagingCostCny
                   + laborCostCny + freightCostCny + otherCostCny
profitCny        = revenueCny − totalCostCny
margin           = revenueCny > 0 ? (profitCny / revenueCny × 100) : 0   （百分数，4 位）
```

> **舍入**：所有乘除按 `ROUND_HALF_UP` 保留 4 位（`00` §6.5）。
> **汇率缺失**：`exchangeRate` 置 NULL + 记日志，`*Cny` 项按 0 计入并在 `costSnapshot` 标注「汇率缺失」（**禁止猜汇率**）。

## 12. 本层实施注意事项（draft2）

| # | 事项 | 说明 |
|---|---|---|
| 1 | **CHECK 约束必须手写 SQL** | `QualityInspection` / `Payment` 宿主约束为 **exact-one（二选一）**，无法用 Prisma schema 表达，须在 migration 中手写；`migrate dev` 不会检测其存在与否（见 §5.1 / §8.2） |
| 2 | **不得出现 `SalesOrder.inspections`** | Q14：QC 不挂订单，经 `ProductionOrder` / `Shipment` 间接追溯 |
| 3 | **不得出现 `SampleOrder.salesOrderId`** | Q10 / 第三批：来源关系只在 `SalesOrder.sampleOrderId`（**非 unique**，1:N）；`SampleOrder` 侧仅 `salesOrders[]` 反向 |
| 4 | **不得出现 `SalesOrder.approvalRecords[]`** | 审批为多态旁挂（`01` §4） |
| 5 | **本层无 `deletedAt`** | Q9：软删除仅 `User`/`Supplier`/`Product`/`Customer` 四张表 |
| 6 | **金额/汇率/比率全部 `Decimal`** | 金额 18,4；单价 18,6；数量 18,4；汇率 18,8；比率 9,4（`00` §6.5）；`Float` 仅用于 `grossWeight/netWeight/volume` |
| 7 | 数量口径 | 成交/生产/出货/采购**单据行**数量用 `Decimal(18,4)`；`SampleOrder.quantity` / `OpportunityItem.quantity` / `LeadItem.quantity` 为**意向数量**，保留 `Int` |
| 8 | 运费换算口径 | `freightAmountCny` 必须显式写入；汇率缺失时置 NULL 并记日志，禁止猜汇率 |
| 9 | `Profit` 成本来源 | 采购成本按 `purchaseType` 三分类汇总；`freightCostCny` 只来自 `Shipment.freightAmountCny` |
| 10 | `PurchaseOrderItem.productionOrderItemId` 跨表校验 | 若非空，`productionOrderItem.productionOrder.salesOrderId` 必须等于 `purchaseOrder.salesOrderId`（应用层） |
| 11 | `PurchaseOrder.status` | 旧列为 `String @default("DRAFT")`（`DRAFT`/`ORDERED`/`PARTIAL`）→ `PurchaseStatus`，迁移须走 `String → enum` 两阶段（`05` §10）。**注意**：`ProductionOrderItem.status` / `PurchaseOrderItem.status` / `PurchaseOrder.purchaseType` 在旧库**无对应表/列**（旧库无这两张明细表，旧 `PurchaseOrder` 也没有 `purchaseType`），属**新建**，**不需要**两阶段 |
| 12 | `SalesOrder.sampleOrderId` 迁移 | 旧 `SampleOrder.salesOrderId`（draft1 双向）在实施时必须**搬迁并 DROP 旧列**，见 `05` §4.4。**注意**：第三批已把该 FK 定为 **1:N（非 unique）**，而 `05` §4.4 仍写 `@unique`，需在后续批次同步 |
| 13 | `SampleOrder` **不加 `quotationId`** | 第三批 §9：打样与报价保持**间接关系**（经 `opportunityId` 追溯）；免费打样 / 老客重打 / 内部开发样 / 直接样品需求都可能没有正式报价单 |
| 14 | `SalesOrder.quotationId` 可空 | 第三批 §10：`NULL` 合法（老客复购 / 固定价 / 框架订单）；一个报价可产生多张订单（1:N），**不得**加 `@unique`；完整矩阵见 §13 |
| 15 | QC / Payment 宿主 FK 用 `onDelete: Restrict` | exact-one CHECK 与 `SetNull` **不兼容**（置空会立刻违反 CHECK）；`Restrict` 表达「QC 是历史证据，宿主不可被静默删除」 |
| 16 | `Payment.customerId` 语义 | 辅助业务主体字段，**不承担主宿主关系**；与宿主/方向的一致性走 **V1.0 应用层一致性校验**，不新增复杂 FK |
| 17 | **无双向重复 FK** | 每对关系只有 1 条真实 FK，另一侧仅 Prisma 反向 relation；`SalesOrder.profit` 为**单数**（`Profit.salesOrderId @unique`） |

## 13. 销售-履约最终关系矩阵（第三批定稿）

> **口径**：「必须」= 该实体**创建时**需要该业务来源，**不表示**整条链每次都要经过。整条链是「**可追溯关系链**」，不是强制工作流。

| 来源 | 目标 | 关系 | 是否必须 |
|---|---|---|---|
| Customer | Opportunity | 1:N | 必须 |
| Lead | Opportunity | 1:N | Opportunity 可选来源 |
| Opportunity | Quotation | 1:N | 必须 |
| Quotation | Customer | N:1 | 必须 |
| Opportunity | SampleOrder | 1:N | 可选 |
| Opportunity | SalesOrder | 1:N | 必须 |
| Quotation | SalesOrder | 1:N | 可选 |
| SampleOrder | SalesOrder | 1:N | 可选 |
| SalesOrder | ProductionOrder | 1:N | 必须 |
| SalesOrder | Shipment | 1:N | 必须 |
| ProductionOrder | QualityInspection | 1:N | 二选一宿主 |
| Shipment | QualityInspection | 1:N | 二选一宿主 |
| SalesOrder | Payment | 1:N | 可选 |
| PurchaseOrder | Payment | 1:N | 可选 |

**真实 FK 落位表（每对关系只有 1 条真实 FK，另一侧仅 Prisma 反向 relation）**

| 关系 | 真实 FK 所在 | 反向 relation | 基数 | 约束 |
|---|---|---|---|---|
| Lead ↔ Opportunity | `Opportunity.leadId @unique` | `Lead.opportunity` | 1:1 | 全系统唯一 |
| Customer → Opportunity | `Opportunity.customerId` | `Customer.opportunities[]` | N:1 | — |
| Customer → SampleOrder | `SampleOrder.customerId` | `Customer.sampleOrders[]` | N:1 | — |
| Opportunity → Quotation | `Quotation.opportunityId` | `Opportunity.quotations[]` | N:1 | — |
| Opportunity → SampleOrder | `SampleOrder.opportunityId?` | `Opportunity.sampleOrders[]` | N:1 | 可空 |
| Opportunity → SalesOrder | `SalesOrder.opportunityId` | `Opportunity.salesOrders[]` | N:1 | — |
| Quotation → SalesOrder | `SalesOrder.quotationId?` | `Quotation.salesOrders[]` | N:1 | 可空，**非 unique** |
| SampleOrder → SalesOrder | `SalesOrder.sampleOrderId?` | `SampleOrder.salesOrders[]` | N:1 | 可空，**非 unique**（第三批） |
| SalesOrder → ProductionOrder | `ProductionOrder.salesOrderId` | `SalesOrder.productionOrders[]` | N:1 | — |
| SalesOrder → Shipment | `Shipment.salesOrderId` | `SalesOrder.shipments[]` | N:1 | — |
| ProductionOrder → QC | `QualityInspection.productionOrderId?` | `ProductionOrder.inspections[]` | N:1 | **exact-one**，`Restrict` |
| Shipment → QC | `QualityInspection.shipmentId?` | `Shipment.inspections[]` | N:1 | **exact-one**，`Restrict` |
| SalesOrder → Payment | `Payment.salesOrderId?` | `SalesOrder.payments[]` | N:1 | **exact-one** |
| PurchaseOrder → Payment | `Payment.purchaseOrderId?` | `PurchaseOrder.payments[]` | N:1 | **exact-one** |
| CustomerProduct → SalesOrderItem | `SalesOrderItem.customerProductId?` | `CustomerProduct.salesOrderItems[]` | N:1 | 可空 |
| SalesOrder → Profit | `Profit.salesOrderId @unique` | `SalesOrder.profit` | 1:1 | 一单一条 |

**多态旁挂（不是 FK，禁止声明 Prisma 反向 relation）**：`ApprovalRecord(bizType, businessId)`、`Attachment(ownerType, ownerId)` —— `Quotation` / `SalesOrder` / `LeadItem` / `QualityInspection` 等**不得**声明 `approvalRecords[]` / `Attachment[]`。

**支持的业务场景（关系设计不得把这些场景锁死）**

| 场景 | 链路 |
|---|---|
| A 新客户完整流程 | Lead → Customer → Opportunity → Quotation → SampleOrder → SalesOrder → ProductionOrder → QC → Shipment → Payment |
| B 老客户直接下单 | Customer → Opportunity → SalesOrder → ProductionOrder → Shipment |
| C 无需打样 | Opportunity → Quotation → SalesOrder |
| D 报价失败 | Opportunity → Quotation → `REJECTED`（配合 `outcome = LOST`） |
| E 多轮打样 | Opportunity → SampleOrder → SampleRound 1..N → SalesOrder |
| F 部分生产 / 多次出货 | SalesOrder → ProductionOrder ×N → Shipment 1..N |
