# 01 · L0 公共支撑层（13 张业务表）

> 平台内核，与业务解耦。本层**基本沿用**现有设计（审计未发现结构性问题），仅做三类加固：① 审计字段规范与**软删除白名单**；② 抽出「编号 / 附件 / 审批流水」三个被散落在 controller 里的横切能力；③ 状态取值随新单据枚举同步。
> 审计映射：`P2-1`（编号散落）、`P0-6`/`P2-2`（附件与凭证无统一存储）、`P1-9`（审批只有配置无流水）。
> **draft2 修订**：`AttachmentOwnerType` 补 4 个明细级宿主；`DailyExchangeRate.ratePerCNY` → `rateToCny`（`Decimal(18,8)`，方向统一）、`date String "YYYY-MM-DD"` → `DateTime @db.Date`（遵循 `00` §2 原则 6）；`Attachment` 去 `deletedAt`；`Currency` 枚举上移到本层；`NumberSequence` 补实施规则；`ApprovalRecord` 明确「不在宿主上声明反向 relation」。
> **draft2 修订（第二批 · 公共基础层规范统一）**：新增 §1.2~§1.7 全库通用规范——金额 / 汇率 / 比例一律 `Decimal` 且精度唯一（金额 `(18,2)`、单价 `(18,6)`、数量 `(18,4)`、汇率 `(18,8)`、比例 `(9,4)`）；`Float` 仅限物理测量量；`Currency` 13 值唯一定义且 enum 默认值**不加引号**；JSON 字段统一 `Json?` + Zod（**不含** `type FeatureFlags`）；Decimal API 输出统一为字符串；`amountCny = amount × rateToCny`（CNY ⇒ `rateToCny = 1`）；`DailyExchangeRate.date` 用 `DateTime @db.Date`。

### 1.2 数值类型规范（全库总规则）

**适用范围**：`01`~`04` 全部模型。**金额 / 汇率 / 比例 / 百分比 一律 `Decimal`，禁止 `Float`。**

| 语义 | Prisma | PostgreSQL | 说明 |
|---|---|---|---|
| 金额（原币 / 本位币） | `Decimal @db.Decimal(18, 2)` | `numeric(18,2)` | 分位精度 |
| 单价 | `Decimal @db.Decimal(18, 6)` | `numeric(18,6)` | 外贸单价常见 0.0001 USD 级 |
| 数量 | `Decimal @db.Decimal(18, 4)` | `numeric(18,4)` | 支持 kg / m 等非整数 |
| 汇率 | `Decimal @db.Decimal(18, 8)` | `numeric(18,8)` | JPY / KRW 折算需 8 位 |
| 比例 / 百分比 | `Decimal @db.Decimal(9, 4)` | `numeric(9,4)` | **百分数语义** |

- **禁止**：金额 / 汇率 / 比例 / 百分比 / 税率 / 折扣率 / 毛利率 / 佣金比例 / 任何财务计算数值使用 `Float`、`@db.Real`、`@db.DoublePrecision`。
- **允许 `Float`**：仅**物理测量量** —— 长度 / 宽度 / 高度 / 厚度 / 重量 / 体积 / 尺寸（`sizeL/sizeW/sizeH`、`weight`、`volume`、`customSizeL/W/H`、`customWeight`、`grossWeight/netWeight` 等）。
- **百分比语义 = 0–100**（**不是** 0–1）：`13.0000` = 13%、`100.0000` = 100%、`0.5000` = 0.5%；适用于 `taxRate` / `discount` / `ratio` / `margin` / `probability`（ADR-19 / Q13）。
- 本表为**唯一精度来源**（与 `00` §6.5 同步），`02`~`04` 不得另立标准。

> 关联：`00` §2 原则 5 / 原则 11、§6.5、ADR-16。

### 1.3 币种（Currency）规范

- **唯一来源**：`Currency` 枚举仅在 §1.1 定义一次（**13 值**），`02` / `03` / `04` 一律引用，**不得重复定义不同版本**。
- 取值：`CNY`(人民币) · `USD`(美元) · `EUR`(欧元) · `GBP`(英镑) · `JPY`(日元) · `HKD`(港币) · `AUD`(澳元) · `CAD`(加元) · `KRW`(韩元) · `RUB`(卢布) · `SEK`(瑞典克朗) · `NOK`(挪威克朗) · `DKK`(丹麦克朗)。
- **本位币固定 `CNY`**（Q4）；报价 / 销售订单默认 `USD`，采购 / 内部费用默认 `CNY`。
- **enum 默认值不得加引号**：✅ `currency Currency @default(CNY)`；❌ `@default("CNY")`（Prisma `enum` 的 `@default` 只接受枚举字面量，不接受字符串）。
- 展示小数位：`JPY` / `KRW` 为 0 位，其余 2 位（**仅展示，不影响存储精度**）。

> 关联：`00` §6.6、本文件 §1.1。

### 1.4 JSON 字段规范（含 FeatureFlags）

- **禁止**设计 Prisma composite `type`（PostgreSQL 目标下不可用）。
- 结构化 / 可变字段统一 `Json?`，**结构由应用层 Zod 校验**：
  - ✅ `features Json?`
  - ❌ `type FeatureFlags`（**不得**作为 PG composite type 使用）
- 逻辑结构在文档中说明即可，例如：
  ```json
  { "quotationV2": true, "customerProduct": true, "profit": true }
  ```
- 具体 JSON 的字段结构由**所属层**给出 Zod Schema（如 `Product.features` 见 `02` §2.1）。
- **不得**用 JSON 代替明细表（`00` §2 原则 4）。

### 1.5 Decimal 的 API 序列化规范

- 所有 `Decimal` 字段（金额 / 汇率 / 比例）经 API 返回时**统一序列化为字符串**：

  ```json
  { "amount": "1250.50", "amountCny": "9003.60", "rateToCny": "7.20000000" }
  ```

- **禁止**在 API 层把 `Decimal` 转成 JS `Number`。
- 前端**禁止**用 JS `number` 做金额 / 汇率 / 比例运算（`+` / `toFixed()` 会静默出错），需要时使用 `decimal.js` 或后端计算结果。
- 前端提交金额 / 汇率**一律传字符串**，后端 `new Prisma.Decimal(str)` 校验后入库。
- **存储精度与展示精度分离**（存储 2 / 6 / 8 / 4 位；展示按币种 0~2 位）。
- 本批次仅记录架构规则，**不改前端代码**。

> 关联：`00` §6.5「API 序列化」、ADR-16、Q7。

### 1.6 本位币（CNY）换算规范

```
非 CNY：amountCny = amount × rateToCny
CNY   ：rateToCny = 1，amountCny = amount
```

- `exchangeRate`（单据快照字段）语义 **= `rateToCny`**：1 单位原币 = x CNY。
- **禁止**在正向业务逻辑中使用 `amount / exchangeRate` 反向换算（仅允许补数脚本）。
- 汇率缺失：单据 `exchangeRate` 置 `NULL` + 记日志（**禁止猜汇率、禁止按 1.0 入库**）；**CNY 例外——恒为 `1`**。
- 汇率来源：下单日 `DailyExchangeRate(date, currencyCode)` 快照进单据（见 §5.3）。

> 「历史迁移中缺汇率的处理」属迁移文档（`05`）范围，本批不涉及。

### 1.7 日期规范

- 业务日期统一 `DateTime`；**仅日期语义**（无时间）用 `DateTime @db.Date`（PG `DATE`）。
- **废弃** `String "YYYY-MM-DD"` 存业务日期；时区统一 `Asia/Shanghai`、存 UTC。
- 唯一日期特例形态见 §5.3：`DailyExchangeRate.date` = **汇率生效日期**，不含时间（`DateTime @db.Date`）。

> 关联：`00` §2 原则 6。

## 4. 审批（2 张）

```prisma
/// 审批流程配置：按业务类型配置审批人（沿用旧 ApprovalConfig，取值改枚举）
model ApprovalConfig {
  id            String          @id @default(uuid())
  bizType       ApprovalBizType @unique   // 旧字段名 type → bizType（RENAME COLUMN）
  approverIds   String          // JSON 数组，兼容旧格式
  approverNames String?
  /// 新增：多级审批预留，JSON: [{level, approverIds:[], mode:"ANY"|"ALL"}]
  flow          Json?
  enabled       Boolean         @default(true)
  createdAt     DateTime        @default(now())
  updatedAt     DateTime        @updatedAt
}

/// 审批流水：一次提交产生一条，记录每一步处置。
/// 采用 bizType + businessId 多态旁挂：宿主模型（Quotation / SalesOrder / ...）上
/// **不得**声明 `approvalRecords ApprovalRecord[]` 反向 relation（否则形成无约束多态 FK）。
model ApprovalRecord {
  id           String          @id @default(uuid())
  bizType      ApprovalBizType
  businessId   String
  businessNo   String?
  level        Int             @default(1)
  status       ApprovalStatus  @default(PENDING)
  submittedBy  String?
  submittedAt  DateTime        @default(now())
  approverId   String?
  approvedAt   DateTime?
  comment      String?
  @@index([bizType, businessId])
  @@index([approverId, status])
}
```

> **为什么要新增 `ApprovalRecord`**：旧版只有 `ApprovalConfig`（配置谁审批），**没有任何审批流水表**。审计 P1-9 确认：当前审批态（`Order.status = SUBMITTED/APPROVED`）直接由前端传值写库，谁审的、何时审的、审批意见均不可追溯。主链中报价与订单都需要审批留痕。

> **多态旁挂的使用约定（ADR-13/原则 10 的一致性）**
> 1. 查询宿主审批记录：`ApprovalRecord.findMany({ where: { bizType, businessId } })`；
> 2. **不得**在宿主模型上声明反向 relation（draft1 的 `Quotation.approvalRecords[]`、`SalesOrder.approvalRecords[]` 已全部删除）；
> 3. 审批若需要参与权限过滤/统计，改由 `bizType` 白名单 + 应用层校验，不建 FK。

## 5. 基础能力（3 张）

### 5.1 `NumberSequence`（统一发号）

```prisma
/// 统一编号生成器。业务表只存结果编号，禁止在 controller 内拼接。
/// 例：{ prefix: "SO", datePattern: "yyyyMMdd", padding: 4 } → SO-20260913-0001
model NumberSequence {
  id          String   @id @default(uuid())
  code        String   @unique // LEAD / OPP / QUO / SMP / SO / PO / PR / SHP / INS / PAY / PRF / CUS / PRD / SUP / CMB
  name        String
  prefix      String
  datePattern String   @default("yyyyMMdd") // yyyyMMdd / yyyyMM / ""
  padding     Int      @default(4)
  /// 当前周期标识，如 "20260913"；周期变化时归零
  currentPeriod String @default("")
  currentValue  Int    @default(0)
  /// 乐观锁辅助字段（行锁为主，version 用于审计与排障）
  version     Int      @default(0)
  updatedAt   DateTime @updatedAt
}

/// 编号规则登记（文档化，不落库）
/// LEAD  → XS-yyyyMM-0001   线索号
/// OPP   → BO-yyyyMMdd-0001 商机号
/// QUO   → QU-yyyyMMdd-0001 报价单号
/// SMP   → SM-yyyyMMdd-0001 打样单号
/// SO    → SO-yyyyMMdd-0001 销售订单号
/// PO    → PO-yyyyMMdd-0001 生产工单号
/// PR    → PR-yyyyMMdd-0001 采购单号
/// SHP   → SH-yyyyMMdd-0001 出货单号
/// INS   → QC-yyyyMMdd-0001 质检单号
/// PAY   → PY-yyyyMMdd-0001 收付款单号
/// PRF   → PF-yyyyMMdd-0001 利润单号
/// CUS   → CUS-yyyyMMdd-0001 客户编号
/// PRD   → PRD-yyyyMMdd-0001 产品编号
/// SUP   → SUP-yyyyMMdd-0001 供应商编号
/// CMB   → CMB-yyyyMMdd-0001 组合产品编号（`02` §5 `ComboProduct.comboNo`）
```

**取号算法（伪代码）**

```
BEGIN;
  SELECT * FROM "NumberSequence" WHERE code = $1 FOR UPDATE;   -- 行锁
  period = format(now(), datePattern);
  IF period <> currentPeriod THEN currentValue = 0; currentPeriod = period; END IF;
  currentValue = currentValue + 1;
  UPDATE "NumberSequence" SET currentValue, currentPeriod, version = version + 1 WHERE id = ...;
COMMIT;
RETURN prefix || '-' || period || '-' || lpad(currentValue, padding, '0');
```

**实施规则（硬性，draft2 补充）**

| # | 规则 | 说明 |
|---|---|---|
| 1 | 取号**必须**在 `prisma.$transaction` 内完成 | 用 `prisma.$transaction(async (tx) => { ... })` 包裹 `SELECT ... FOR UPDATE` 与 `UPDATE` |
| 2 | 使用**数据库行锁**（`SELECT ... FOR UPDATE`） | 通过 `tx.$queryRaw` 执行；禁止用 `findFirst` + `update` 两步非锁定读 |
| 3 | 支持**跨周期归零** | `currentPeriod` 与当前 `datePattern` 格式化的周期串不一致时，先归零再自增 |
| 4 | 支持**并发取号** | 同一 `code` 的并发请求串行化在行锁上；不同 `code` 互不阻塞（行级锁） |
| 5 | 同一序列**不得生成重复编号** | 依赖行锁 + `code` 唯一索引 + 业务表编号字段 `@unique` 三重保障 |
| 6 | **禁止**用 `count() + 1` 生成编号 | 删除数据会造成编号回退/重号 |
| 7 | **禁止**用 SQL `row_number()` 作为正式业务编号 | 仅可用于**历史数据补号脚本**（且需与 `currentValue` 同步，见 `05` §5） |
| 8 | 必须考虑**事务回滚后的编号行为** | 取号与业务写入在**同一事务**内：业务回滚 → 编号一并回滚（不会产生跳号）；若采用独立事务取号，则允许跳号但**绝不允许重号**——V1 选择**同一事务**方案 |
| 9 | 发号结果只写业务表编号字段 | 禁止在 controller / service 内散落拼接编号 |

### 5.2 `Attachment`（统一附件）

```prisma
model Attachment {
  id         String              @id @default(cuid())
  ownerType  AttachmentOwnerType
  ownerId    String
  /// 分类：IMAGE / DRAWING(设计稿) / VOUCHER(付款凭证) / CONTRACT / INSPECTION_REPORT / OTHER
  category   String              @default("OTHER")
  fileName   String
  filePath   String
  fileSize   Int?
  mimeType   String?
  sort       Int                 @default(0)
  uploadedBy String?
  createdAt  DateTime            @default(now())
  @@index([ownerType, ownerId])
  @@index([category])
}
```

**边界说明（对应设计原则 10）**

| 允许用 `Attachment` 多态的场景 | 不允许的场景 |
|---|---|
| 产品图片、设计稿、认证文件、付款凭证、质检报告、单据行图片 | 单据之间的业务引用（如 `Order.targetType/targetId`） |

- 违规判定标准：若对象需要参与**权限过滤 / 状态流转 / 统计聚合 / 外键完整性**，必须建独立外键；仅「图片/文件」这类纯旁挂资源才可用 `Attachment`。
- 各业务表如需主图，保留 `coverImage String?` 冗余字段（避免列表页 join `Attachment`）。
- **`Attachment` 不声明 `deletedAt`**（Q9：软删除仅 4 张主数据表）。附件删除 = 物理删除 + 定时孤儿清理（`ownerType/ownerId` 无宿主时回收），清理策略见 `00` §7.2 R2。
- **单据行图片（`LeadItem` 等）的统一实现**：不在业务行模型上声明 `Attachment[]`（Prisma 中不存在该 relation，draft1 的 `LeadItem.images Attachment[]` 已删除），而是：
  ```ts
  // 查询侧
  prisma.attachment.findMany({ where: { ownerType: 'LEAD_ITEM', ownerId: leadItemId } })
  ```
  写入侧同理，`ownerType` 取明细级枚举值（`LEAD_ITEM` / `OPPORTUNITY_ITEM` / `QUOTATION_ITEM` / `SALES_ORDER_ITEM`）。

### 5.3 `DailyExchangeRate`（汇率）

```prisma
model DailyExchangeRate {
  id           String   @id @default(uuid())
  /// 汇率生效日期：仅日期、不含时间（Prisma `DateTime @db.Date` ↔ PG `DATE`；遵循 `00` §2 原则 6，见 §1.7）
  date         DateTime @db.Date
  currencyCode Currency // USD / EUR / GBP / JPY / ...（引用 01 §1 的 Currency 枚举）
  /// 语义：1 单位目标币种 = rateToCny CNY（如 USD → 7.2 表示 1 USD = 7.2 CNY）
  rateToCny    Decimal  @db.Decimal(18, 8)
  createdAt    DateTime @default(now())
  @@unique([date, currencyCode], name: "daily_rate_unique")
}
```

**汇率语义统一（ADR-18 / P1-2 定案）**

| 场景 | 统一规则 |
|---|---|
| 本表字段 | `rateToCny`，语义 **1 单位目标币种 = X CNY**（USD 7.2 / EUR 8.35 / JPY 0.048） |
| 单据字段 | `exchangeRate`，语义**与 `rateToCny` 完全一致**（1 原币 = x CNY） |
| 原币 → 本位币 | `amountCny = amount × rateToCny`（`exchangeRate` ≡ `rateToCny`，见 §1.6） |
| 反向换算 | **禁止**在正向业务逻辑中使用 `amount / exchangeRate`；仅允许出现在历史数据补数脚本中 |
| 汇率来源 | 下单日 `DailyExchangeRate(date, currencyCode)` **快照进单据**，之后不再随汇率变动 |
| 汇率缺失 | `exchangeRate` 置 `NULL` + 记日志（**禁止猜汇率、禁止按 1.0 入库**） |
| CNY | `rateToCny = 1`、`amountCny = amount`（CNY 无需换算，见 §1.6） |
| 禁止命名 | 不得出现 `rate` / `cnyRate` / `rateToUsd` 等**方向不明或反向**的汇率字段名 |
| 日期字段 | `date` 用 `DateTime @db.Date`（PG `DATE`），**禁止** `String "YYYY-MM-DD"`（原则 6）；`@@unique([date, currencyCode])` ⇒ 同一天 + 同一币种仅一条 |

> **draft1 已废弃写法（不得再出现）**：
> - 字段名 `ratePerCNY`；
> - 反向注释「1 CNY = ratePerCNY 目标币种」「1 CNY = 目标币种汇率」；
> - 任何形式的 `/ rateToCny`、`* ratePerCNY`；
> - 方向不明的字段名 `rate` / `cnyRate` / `rateToUsd`。

> **唯一性语义（硬性）**：`@@unique([date, currencyCode])` ⇒ **同一天 + 同一币种只能存在一条汇率记录**；`date` 为汇率**生效日期**（不含时间，PG `DATE` ↔ Prisma `DateTime @db.Date`）。
