# 03 · L2 销售层（11 张表）

> 销售层 = `Lead → Customer → Opportunity → Quotation`，**不包含任何履约状态**。
> 本层是审计 `P0-1`（`SalesPipeline` 四合一）的拆解落点，也是 `P0-7`（三套报价并存）的收敛点。
> 上游依赖：`01`（User / Role / NumberSequence / Attachment / DailyExchangeRate / **Currency**）、`02`（Product / Channel / CustomerType）。
> **draft2 修订**：`Opportunity.stage` 改**派生不落库** + 新增 `outcome`；拆开 `intentLevel` / `probability`；删除 `Lead.opportunityId`；删除 `LeadItem.images`；`ProductPrice` **彻底删除 `customerProductId`**（重定义为「客户级标准产品价格」）且 `customerId` 必填；全部金额改 `Decimal`；`Quotation`/`Opportunity`/`Lead` 去 `deletedAt`。
> **第三批复核（销售 ↔ 履约关系）**：`Quotation` 1:N `SalesOrder`（真实 FK 在 `SalesOrder.quotationId`，**可空**）；`SampleOrder` 与 `Quotation` 保持**间接关系**（**不加 `quotationId`**）；`Opportunity.leadId @unique` 仍是全系统唯一 Lead ↔ Opportunity 外键；`Opportunity.stage` 不落库、终态走 `outcome`；`probability`（`Decimal`，0–100）与 `intentLevel` 分离。完整跨层关系矩阵见 `04` §13。

## 1. 枚举定义

```prisma
/// 线索状态（销售漏斗前 3 段）
enum LeadStatus {
  NEW        // 新建
  CONTACTED  // 已联系
  QUALIFIED  // 已确认有效
  CONVERTED  // 已转商机（终态）
  INVALID    // 无效线索（终态）
}

enum LeadSource {
  MANUAL     // 手工录入
  EXCEL      // Excel 导入
  RPA        // RPA 抓取
  SYNC       // 第三方同步
}

/// 商机终态（ADR-03 / Q8 定案：显式落库）。
/// 注意：漏斗阶段（OPPORTUNITY / QUOTING / NEGOTIATION）**派生自下游单据，不落库**，
/// 因此本枚举只表达终态结论，不含阶段值。
enum OpportunityOutcome {
  OPEN  // 进行中
  WON   // 赢单
  LOST  // 输单
}

enum QuotationStatus {
  DRAFT
  SUBMITTED    // 已提交审批
  SENT         // 已发送客户
  ACCEPTED     // 客户接受
  REJECTED     // 客户拒绝
  EXPIRED      // 已过有效期
}

/// 客户等级
enum CustomerLevel {
  DIAMOND   // 钻石客户
  STRATEGIC // 战略客户
  PREMIUM   // 优质客户
  NORMAL    // 普通客户
  POTENTIAL // 潜在客户
}

/// 客户意向等级（主观，人填）—— 与 probability（客观成交概率）是两个维度
enum IntentLevel {
  LOW      // 低意向
  MEDIUM   // 中意向
  HIGH     // 高意向
  READY    // 准成交
}
```

> `Currency` 枚举（13 值）定义在 `01` §1，本层不得重复定义。
> **draft1 的 `enum OpportunityStage` 已删除**（不得再出现落库的 `Opportunity.stage`）。

**商机四维度（不得互相替代）**

| 维度 | 是否落库 | 语义 | 取值 | 维护方 |
|---|---|---|---|---|
| `stage` | ❌ **派生** | 漏斗推进到哪一步（客观，由下游单据推导） | `OPPORTUNITY` / `QUOTING` / `NEGOTIATION` | `server/src/utils/pipelineStage.ts` |
| `outcome` | ✅ 落库 | 商机终态结论 | `OPEN` / `WON` / `LOST` | 系统（`WON`）/ 人工（`LOST`） |
| `intentLevel` | ✅ 落库 | 客户意向等级（主观） | `LOW` / `MEDIUM` / `HIGH` / `READY` | 人工 |
| `probability` | ✅ 落库 | 成交概率 0~100（百分数语义） | `Decimal(5,2)` | 人工（V1），后续可按规则计算 |

**派生 stage 的推导口径（`pipelineStage.ts` 最终职责）**

| 派生值 | 判定条件 |
|---|---|
| `OPPORTUNITY` | 无任何下游单据 |
| `QUOTING` | 存在 ≥1 张 `Quotation`（未 `REJECTED`/`EXPIRED`） |
| `NEGOTIATION` | 存在 ≥1 张 `SampleOrder`（`APPROVED`）或 ≥1 张 `SalesOrder` |

> 实施阶段需同步改造 `pipelineStage.ts`：① 查询对象由 `prisma.order.findMany({ where: { pipelineId } })` 改为 `quotation` / `sampleOrder` / `salesOrder`；② **修正 `STAGE_ORDER` 排序**（旧实现 `SHIPPED=5 < ORDER=6`，会返回错误的「最新阶段」）；③ **不再返回终态**（`WON`/`LOST` 由 `outcome` 提供）。

### 2.1 相对旧 `Customer` 的字段去向

| 旧字段 | 新去向 | 理由 |
|---|---|---|
| `customerCode String? @unique` | `customerNo String @unique`（必填） | 编号缺失导致列表无法引用；统一由 `NumberSequence` 生成。**旧列为 nullable unique（允许多行 NULL），改必填前必须补号**（见 `05` §5） |
| `images`（JSON 字符串） | `coverImage` + `Attachment(ownerType=CUSTOMER)` | P0-4 |
| `tags`（逗号字符串） | `String[]` | PG 原生数组，可 `has` 查询 |
| `firstOrderDate String?` | `firstOrderAt DateTime?` + `lastOrderAt` + `totalOrderAmountCny` | 字符串日期无法排序；订单统计应落库而非每次聚合 |
| `estimatedAmount Float?` | **移出** → `Opportunity.estimatedAmount` | 预计金额是**商机**属性，客户级没有唯一语义（一个客户多个商机） |
| `customerLevel String? @default("普通客户")` | `CustomerLevel` 枚举 | 中文文案落库导致无法国际化、无法排序 |
| `intentLevel String?` | `IntentLevel` 枚举 | 同上 |
| `ownerId` | 保留（语义正确） | 公海基准字段 |
| `customerType` | 保留 `String?` | 沿用旧决策（避外键），见 02 §9 |
| `orders` / `pipelines` | → `salesOrders` / `opportunities` | 随被拆对象改名 |
| — | `deletedAt` | 保留（软删除白名单，Q9） |

### 2.2 `CustomerActivity`（沿用，零结构变更）

```prisma
/// 客户活动流水（沿用旧表，列与旧结构一致，无 deletedAt）。
/// 公海认领/释放、关键客户标记、意向变更等操作均写本表。
model CustomerActivity {
  id         String   @id @default(uuid())
  customerId String
  customer   Customer @relation(fields: [customerId], references: [id], onDelete: Cascade)
  action     String   // CLAIM / RELEASE / CREATED / UPDATED / KEY_TOGGLE / INTENT_CHANGE
  detail     String?
  summary    String?
  diff       String?  // JSON: [{field,label,beforeText,afterText}]
  realName   String?
  createdBy  String
  createdAt  DateTime @default(now())
}
```

> **零 DDL**：本表**完全沿用**旧 `CustomerActivity`（列名、类型、`onDelete: Cascade` 均不变），迁移不产生任何 DDL。
> 可选优化（**须独立 migration，不属 V1 必需**）：`@@index([customerId])` —— 旧表未建该索引，PG 不会为外键自动建索引，若「客户详情页活动列表」成为慢查询热点再补。
> 与 `OperationLog` 的分工：`OperationLog` 记录**跨模块审计**（含 `businessType/businessId`），`CustomerActivity` 记录**客户 Timeline 展示**（含 `diff` 供前端渲染变更前后值），两者数据来源不同，**不做合并**。

## 3. `Lead` + `LeadItem`（线索）

### 3.1 模型

```prisma
model Lead {

  contactMethod String?  // 微信号/旺旺/WhatsApp

model LeadItem {

  leadId    String
  lead      Lead     @relation(fields: [leadId], references: [id], onDelete: Cascade)
  productId String?

  /// 未建档产品时直接记录名称（待确认建档）
```

> **`LeadItem` 的图片实现（不得使用 `Attachment[]`）**
> draft1 的 `images Attachment[]` **不是合法的 Prisma relation**（`Attachment` 是多态旁挂表，不存在反向字段），已删除。
> 正确做法（见 `01` §5.2）：
> ```ts
> // 查询
> prisma.attachment.findMany({ where: { ownerType: 'LEAD_ITEM', ownerId: leadItemId } })
> // 写入：上传时传 ownerType='LEAD_ITEM', ownerId=leadItemId
> ```
> 为此 `AttachmentOwnerType` 已补充 `LEAD_ITEM` / `OPPORTUNITY_ITEM` / `QUOTATION_ITEM` / `SALES_ORDER_ITEM` 四个明细级枚举值（`01` §1）。
> **不得**为 `LeadItem` 增加 `attachmentId` / `leadItemId` 之类的真实外键（会让 `Attachment` 同时拥有两套宿主语义）。

### 3.2 相对旧 `Lead` 的字段去向

| 旧字段 | 新去向 | 理由 |
|---|---|---|
| `leadNumber String?` | `leadNo String @unique` | 编号必填 + 唯一约束；**旧列为 nullable 且无唯一约束**，改必填前必须补号并去重（`05` §5） |
| `pipelineId String? @unique` | **删除**（FK 迁移至 `Opportunity.leadId`） | 旧列指向 `SalesPipeline`，是「线索 → 商机」的真实外键。新模型把外键放在 `Opportunity` 一侧，因此旧 FK 必须**搬迁**并回填（`05` §3.3 有完整步骤）；**不得**保留 `Lead.opportunityId` |
| `productId` + `quantity`（单产品） | → `LeadItem[]`（多产品） | 旧版同时存在 `Lead.productId` 单产品与 `LeadProduct` 多产品两条路径，**双实现**；统一为 `LeadItem` |
| `status`：`NEW/CONTACTED/QUALIFIED/INVALID/CONVERTED/VALID` | `LeadStatus`（去掉 `VALID`） | `VALID` 与 `QUALIFIED` 语义重复，属历史遗留 |
| `images`（JSON 数组字符串） | → `Attachment(ownerType=LEAD)` | P0-4 |
| `assignedTo` | `ownerId` | 归属字段统一（`P1-2`） |
| `sourceChannel`（存「渠道/平台」完整路径字符串） | **删除** → `channelId` + `shopId` | 冗余字段，已有结构化外键 |
| `productType` / `productDesc` | 合并进 `productInterest` + `specialReq` | 三个字段语义重叠 |
| `productName` | 保留 | 未建档产品场景 |
| `createdBy` | 保留 | — |
| `deletedAt`（draft1 新增） | **删除** | Q9：软删除仅 4 张主数据表；线索用 `status = INVALID` / `CONVERTED` 表达 |

## 4. `Opportunity` + `OpportunityItem`（商机）

### 4.1 模型

```prisma
/// 商机：销售漏斗的中段载体。仅承载「销售」语义，不复用订单/打样字段。
/// `stage` 为派生字段（不落库，由 pipelineStage.ts 计算）；`outcome` 为落库终态。
model Opportunity {
  id            String @id @default(cuid())
  opportunityNo String @unique   // BO-yyyyMMdd-0001

  title      String
  customerId String
  customer   Customer @relation(fields: [customerId], references: [id], onDelete: Restrict)
  /// 真实外键在本侧（全系统唯一一条 Lead ↔ Opportunity 外键）
  leadId     String?  @unique
  lead       Lead?    @relation("OpportunityLead", fields: [leadId], references: [id], onDelete: SetNull)

  // ---------- 终态（唯一落库的结论字段）----------
  outcome     OpportunityOutcome @default(OPEN)
  /// 终态发生时间（WON / LOST 共用；避免与 wonAt 重复）
  outcomeAt   DateTime?
  wonAt       DateTime?   // = outcome 变为 WON 的时间（便于报表直读）
  lostReason  String?

  // ---------- 商务信息 ----------
  estimatedAmount    Decimal?  @db.Decimal(18, 4)
  currency           Currency  @default(USD)
  exchangeRate       Decimal?  @db.Decimal(18, 8)   // 快照：1 原币 = x CNY
  estimatedCloseDate DateTime?
  /// 客户意向等级（主观）
  intentLevel        IntentLevel?
  /// 成交概率 0~100（百分数语义：50.00 = 50%）
  probability        Decimal?  @db.Decimal(5, 2)
  notes              String?

  // ---------- 归属 ----------
  ownerId String?
  owner   User?   @relation("OpportunityOwner", fields: [ownerId], references: [id], onDelete: SetNull)

  // ---------- 下游 ----------
  items        OpportunityItem[]
  quotations   Quotation[]
  sampleOrders SampleOrder[]
  salesOrders  SalesOrder[]
  activities   OpportunityActivity[]

  createdBy String?
  createdAt DateTime  @default(now())
  updatedBy String?
  updatedAt DateTime  @updatedAt

  @@index([outcome])
  @@index([customerId])
  @@index([ownerId])
  @@index([createdAt])
}

/// 商机涉及的产品明细（旧版完全缺失：商机只能挂 1 个隐含产品）
model OpportunityItem {
  id            String @id @default(cuid())
  opportunityId String
  opportunity   Opportunity @relation(fields: [opportunityId], references: [id], onDelete: Cascade)
  productId     String?
  product       Product? @relation(fields: [productId], references: [id], onDelete: SetNull)
  productName   String           // 快照
  spec          String?          // 规格要求
  quantity      Int      @default(1)
  targetPrice   Decimal? @db.Decimal(18, 6)
  currency      Currency @default(USD)
  remark        String?
  sort          Int      @default(0)
  createdAt     DateTime @default(now())
  updatedAt     DateTime @updatedAt
  @@index([opportunityId])
  @@index([productId])
}

/// 销售活动记录（替代 SalesActivity，删除 fromStage/toStage 死字段）
model OpportunityActivity {
  id            String   @id @default(cuid())
  opportunityId String?
  opportunity   Opportunity? @relation(fields: [opportunityId], references: [id], onDelete: Cascade)
  leadId        String?      // 线索期跟进记录挂此处
  lead          Lead?        @relation(fields: [leadId], references: [id], onDelete: Cascade)
  action        String       // CREATED / STAGE_CHANGE / NOTE_ADDED / QUOTATION_SENT / WON / LOST
  fromStage     String?      // 仅 STAGE_CHANGE 时有值（不再是无条件填充的死字段）
  toStage       String?
  comment       String?
  createdBy     String
  createdAt     DateTime     @default(now())
  @@index([opportunityId])
  @@index([leadId])
}
```

### 4.2 相对旧 `SalesPipeline` 的字段去向（**核心拆解表**）

旧 `SalesPipeline:370-424` 有 5 层业务字段并存，逐字段去向：

| 旧字段 | 归属层 | 新去向 |
|---|---|---|
| `pipelineNumber` | 商机 | `Opportunity.opportunityNo` |
| `title` | 商机 | `Opportunity.title` |
| `customerId` | 商机 | `Opportunity.customerId` |
| `leadId` | 商机 | `Opportunity.leadId`（**真实 FK 在本侧**；`Lead` 侧仅反向 relation） |
| `companyName/contactName/email/phone/country` | — | **删除**，改读 `Customer` / `Lead`（冗余副本，必然不一致） |
| `source` / `productInterest` / `leadNotes` | 线索 | → `Lead.source` / `Lead.productInterest` / `Lead.remark` |
| `estimatedAmount` | 商机 | `Opportunity.estimatedAmount`（`Float?` → `Decimal(18,4)?`） |
| `estimatedCloseDate` | 商机 | `Opportunity.estimatedCloseDate`（`String?` → `DateTime?`） |
| `probability`（存中文文案） | 商机 | **拆两列**：`Opportunity.intentLevel`（枚举，承接中文文案）+ `Opportunity.probability`（`Decimal(5,2)`，可空，后续按规则计算） |
| `opportunityNotes` | 商机 | `Opportunity.notes` |
| `orderAmount/orderDate/deliveryDate/paymentTerms/orderStatus/orderNotes` | 履约 | → `SalesOrder.*`（**彻底离开商机表**） |
| `sampleType/sampleStatus/sampleQuantity/sampleNotes` | 打样 | → `SampleOrder.*` |
| `assignedTo` | 归属 | `Opportunity.ownerId` / `Lead.ownerId`（按实际归属层） |
| `activities` | 日志 | `OpportunityActivity` |
| `leadProducts` | 明细 | `LeadItem` |
| `stage`（旧为派生字段，不落库） | 商机 | **保持派生，不落库**（ADR-03 / Q8）；终态改用 `Opportunity.outcome` 表达 |
| `wonAt` / `lostAt` / `lostReason`（draft1 新增列） | 商机 | 收敛为 `outcomeAt` / `wonAt` / `lostReason` 三列，且仅在 `outcome != OPEN` 时有值 |
| `deletedAt`（draft1 新增） | — | **删除**（Q9） |

> **拆分判定规则**（供后续任何新字段归位使用）：
> ① 该字段是否描述「客户」→ 归 Customer；② 是否只在「未建档阶段」有意义 → 归 Lead；③ 是否只在「有单据后」有意义 → 归对应单据；④ 剩下的销售过程字段 → 归 Opportunity。

### 4.3 `outcome` 的写入规则（Q15 定案）

| 触发 | 动作 |
|---|---|
| `SalesOrder.status` 变为 `CONFIRMED` | `outcome = WON`，`wonAt = now()`，`outcomeAt = now()` |
| 人工标记输单（必填 `lostReason`） | `outcome = LOST`，`outcomeAt = now()` |
| `Quotation.status = ACCEPTED` | **不改变 `outcome`**（客户接受报价 ≠ 最终下单） |
| `Quotation.status = REJECTED` / 超期 `EXPIRED` | **不自动置 LOST**（客户可能换版本再报）；仅提示人工跟进 |
| `outcome = WON` 后订单被 `CANCELLED` | 由业务人工回到 `OPEN` 或置 `LOST`（V1 不自动回滚） |

> `outcome = OPEN` 时不写入 `outcomeAt` / `wonAt` / `lostReason`。

> **第三批复核（Opportunity · 关系与终态）**：
> - `stage` **不作为数据库字段**（不得出现 `stage OpportunityStage`）；阶段继续由 `pipelineStage.ts` 派生。
> - `WON` **不得**写成 `Opportunity.stage = WON`，而是落库 `outcome = WON` + `wonAt` + `outcomeAt`；`WON` 属**最终结果**，不是普通 pipeline stage。
> - 触发口径：`SalesOrder.status = CONFIRMED` → `outcome = WON`（`wonAt` / `outcomeAt` 同步写入）。
> - `probability`（客观成交概率，`Decimal(5,2)`，**0–100 百分数**）与 `intentLevel`（主观意向等级，枚举）是**两个独立字段**，不得互相替代。
> - `Lead ↔ Opportunity` 全系统**只有一条**真实外键：`Opportunity.leadId @unique`。

## 5. 公海与数据范围（销售层规则）

审计 `P1-2`/`P1-3` 指出：旧 `scope.ts` 把「公海」无条件并入所有查询，导致 `dataScope = SELF` 形同虚设，且 `ownerId / assignedTo / createdBy` 三套命名混用。新规则：

### 5.1 归属字段统一

| 对象 | 归属字段 | 是否参与公海 |
|---|---|---|
| `Lead` | `ownerId` | ✅ 是 |
| `Customer` | `ownerId` | ✅ 是 |
| `Opportunity` | `ownerId` | ✅ 是 |
| `Quotation` | `ownerId`（继承商机，可覆盖） | ❌ 否 |
| `Product` | `ownerId` | ❌ 否（产品用 `visibility` 控制，不用公海） |
| `SalesOrder` 及下游 | `ownerId` / 岗位字段 | ❌ 否（履约按项目参与人授权） |
| `PurchaseOrder` | `ownerId`（采购员） | ❌ 否 |

### 5.2 查询范围公式

```
可见集合 =
  [1] 按 Role.dataScope 得到的自有范围
      ALL  → 全部
      DEPT → 本部门及下级部门成员的 ownerId 集合
      SELF → { currentUserId }
  ∪  [2] 仅当该资源「参与公海」且 ownerId IS NULL 时，公海数据

且：[2] 必须额外满足「未被他人认领保护期锁定」
```

### 5.3 与旧实现的差异

| 项 | 旧（`scope.ts`） | 新 |
|---|---|---|
| 公海并入 | 无条件，任何资源都并 | 仅 `Lead`/`Customer`/`Opportunity` 三张表 |
| 归属字段 | `ownerId` / `assignedTo` / `createdBy` 混用 | 统一 `ownerId` |
| 认领保护期 | 无 | 新增 `ownerId IS NULL AND releasedAt > now() - interval 'X day'` 才可被他人认领（防抢单） |

> 保护期时长（建议 7 天）为业务参数，需确认。
> **依赖项登记**：`server/src/utils/scope.ts` 必须按本表重写（公海白名单化），这是 `03` 落地的**必要配套改动**，须列入实施阶段任务清单。

## 7. `CustomerProduct` + `ProductPrice`（产品三层之第 2、3 层）

```prisma
/// 客户定制版本：同一标准品对不同客户的不同定制规格（第 2 层）
model CustomerProduct {
  id         String @id @default(cuid())
  customerId String
  customer   Customer @relation(fields: [customerId], references: [id], onDelete: Restrict)
  productId  String
  product    Product  @relation(fields: [productId], references: [id], onDelete: Restrict)

  version   String  @default("V1")   // 定制版本号
  /// 定制差异（只存与标准品的差异，避免整行复制）
  customName    String?
  customColors  String[] @default([])
  customPackaging String?
  customMaterial  String?
  customSizeL     Float?
  customSizeW     Float?
  customSizeH     Float?
  customWeight    Float?
  customFeatures  Json?     // 同 Product.features 结构
  /// 客户自己的产品编号
  customerSku String?
  logoRequired Boolean @default(false)
  remark      String?

  /// 该定制版本的约定价格（定制价随版本走，不由 ProductPrice 承载）
  agreedPrice    Decimal?  @db.Decimal(18, 6)
  agreedCurrency Currency? @default(USD)

  /// 首次来源：由哪张打样单/报价单确认
  sourceType String?   // SAMPLE_ORDER / QUOTATION / MANUAL
  sourceId   String?

  status    MasterStatus @default(ACTIVE)
  createdBy String?
  createdAt DateTime  @default(now())
  updatedBy String?
  updatedAt DateTime  @updatedAt

  salesOrderItems SalesOrderItem[]  // SalesOrderItem.customerProductId 的反向（04）

  @@unique([customerId, productId, version])
  @@index([productId])
  @@index([customerId])
}

/// 客户级标准产品价格（第 3 层）：**某客户**购买**某标准产品**时的专属价格。
/// Q11 定案：customerId 必填；**彻底不含 customerProductId**（与 CustomerProduct 无外键关联）。
/// 标准价唯一性由 Product.defaultPrice 保证；定制版本价格由 CustomerProduct.agreedPrice 承载。
model ProductPrice {
  id         String @id @default(cuid())
  productId  String
  product    Product  @relation(fields: [productId], references: [id], onDelete: Restrict)
  customerId String   // 必填：本表只存「客户级标准产品价格」
  customer   Customer @relation(fields: [customerId], references: [id], onDelete: Restrict)

  currency  Currency @default(USD)
  price     Decimal  @db.Decimal(18, 6)
  unit      String   @default("PCS")
  minQty    Int      @default(1)
  taxRate   Decimal? @db.Decimal(9, 4)   // 百分数：13 = 13%
  /// 价格来源：报价确认后自动生成
  sourceType String? // QUOTATION
  sourceId   String?
  validFrom  DateTime?
  validTo    DateTime?

  createdBy String?
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  @@unique([productId, customerId, minQty, currency])
  @@index([customerId, productId])
  @@index([validTo])
}
```

> **`ProductPrice` 的收敛（Q11 / ADR-11 / ADR-21）**
> 1. **`customerId` 必填**。draft1 的 `customerId String?` + `@@unique([...customerId...])` 在 PostgreSQL 下**约束失效**（NULL 不参与唯一性判定），可插入任意多条「标准价」。改为必填后约束立即生效。
> 2. **彻底删除 `customerProductId` / `customerProduct` / `@@index([customerProductId])`**（Q11 定案）。V1 中 `ProductPrice` 与 `CustomerProduct` **不再存在任何外键关系**，两者职责严格分离：
>    - `ProductPrice` = **客户级标准产品价格**：「客户 A 买**标准产品** P 多少钱」；
>    - `CustomerProduct.agreedPrice` = **客户定制版本价格**：「客户 A **定制**的 P 版本多少钱」。
>    这样彻底消除 draft1「`customerId = 客户A` 但 `customerProductId` 属于客户 B」的跨列不一致，DB 无需依赖应用层 `customerProduct.customerId === customerId` 校验。
> 3. 相应地，`CustomerProduct` 侧**不得**声明 `prices ProductPrice[]` 反向关系——`ProductPrice` 不再直接属于任何 `CustomerProduct`。

### 7.1 三层产品模型速查

| 层 | 表 | 回答的问题 | 价格字段 |
|---|---|---|---|
| 1 | `Product` | 「我们卖什么标准品」 | `defaultPrice` / `defaultCurrency`（标准价） |
| 2 | `CustomerProduct` | 「某客户要的和他人的有什么不同」（客户定制产品版本） | `agreedPrice` / `agreedCurrency`（定制版本价） |
| 3 | `ProductPrice` | 「某客户买某标准产品多少钱」（客户级标准产品价格） | `price` / `currency` |

> 报价时取值优先级：
> `ProductPrice(客户 + 标准产品) > CustomerProduct.agreedPrice > Product.defaultPrice`
> - 该客户对**标准产品**存在 `ProductPrice` → 取 `ProductPrice.price`；
> - 否则该客户存在命中版本的 `CustomerProduct` 且 `agreedPrice` 非空 → 取 `CustomerProduct.agreedPrice`；
> - 否则回退 `Product.defaultPrice`。
> `Product.defaultPrice` 是**唯一的标准价来源**；`ProductPrice` 只承担**客户级标准产品价格**（与 `CustomerProduct` 无外键绑定），不再承担标准价职责。

## 9. 本层落地后即可回答的业务问题（旧模型无法回答）

1. 「本季度漏斗各段停留了多少单、平均停留多久」→ 派生 `stage` + `Opportunity.outcome` + `OpportunityActivity`
2. 「哪些线索从未被认领」→ `Lead.ownerId IS NULL`
3. 「某商机一共报了几版价、每版差多少」→ `Quotation.version` + 版本链
4. 「某客户买某标准产品的专属价格是多少」→ `ProductPrice`（客户级标准产品价格；`customerId` 必填、**不含 `customerProductId`**）
5. 「某客户的 XX 产品与他人的有什么不同」→ `CustomerProduct`
6. 「销售阶段现在到哪了、是不是丢了」→ 派生 `stage` + `Opportunity.outcome = LOST` + `lostReason`
7. 「这个商机的成交概率是多少、意向多高」→ `probability`（客观，0~100）+ `intentLevel`（主观）**两个独立字段**
8. 「客户接受了报价，为什么还没算赢单」→ `outcome` 只在 `SalesOrder.CONFIRMED` 时置 `WON`（Q15）
