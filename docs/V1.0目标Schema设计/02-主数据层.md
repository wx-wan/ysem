# 02 · L1 主数据层（13 张业务表 + 1 张关联表）

> 主数据 = 全局唯一、被单据引用、不随单据变化的对象。本层重构幅度最大的两张：`Product`（旧 `SingleProduct`）与 `Supplier`。
> 审计映射：`P0-3`（快照缺失根因在主数据与单据耦合）、`P1-5`（产品缺「标准品 / 客户定制版本 / 客户价格」三层）、`P1-6`（`progress` JSON、`certificationIds` 逗号串）、`P0-4`（`images` JSON 字符串）。
> **draft2 修订**：`type FeatureFlags` → `features Json?`；`Float` → `Decimal`；补 3 处反向 relation；`Product ↔ ProductCraft` 关联表**显式化**以保留物理表 `_ProductCraftToSingleProduct`；`ComboProduct` 去 `deletedAt`；`Supplier` 补 `productionOrderItems`。

---

## 2. `Product`（核心重构）

### 2.1 新模型

```prisma
/// 产品主数据 = 「标准品」（不带客户专属信息）。
/// 客户定制版本见 CustomerProduct（03），客户级标准产品价格见 ProductPrice（03）。
model Product {
  id        String  @id @default(cuid())
  productNo String  @unique   // PRD-yyyyMMdd-0001，由 NumberSequence 生成
  name      String
  sku       String? @unique   // 内部 SKU，与 productNo 解耦
  model     String?           // 型号（OEM 必备）

  // ---------- 三级分类 ----------
  crafts     ProductCraftLink[]   // 显式关联表，见 §3.1
  audienceId String?
  audience   ProductAudience?  @relation(fields: [audienceId], references: [id], onDelete: SetNull)
  categoryId String?
  category   ProductCategory?  @relation(fields: [categoryId], references: [id], onDelete: SetNull)

  // ---------- 属性（供应商标记「标准品」的固有属性）----------
  material   String?   // 材质：PVC / ABS / 硅胶 / 搪胶 ...（新增，无旧字段来源）
  sizeL      Float?    // 长 cm（物理量，允许 Float）
  sizeW      Float?    // 宽 cm
  sizeH      Float?    // 高 cm
  weight     Float?    // 克重 g
  colors     String[]  @default([])  // 颜色（潘通色号）
  packaging  String?   // 包装：卡/盒/袋/桶（保留：旧 SingleProduct.packaging）
  /// 功能特性集合（替代旧版 5 个独立 Boolean）。
  /// Prisma 在 PostgreSQL 下**不支持 composite type**，因此用 Json + 应用层 Zod 校验。
  /// 结构约定：{ "logo": boolean, "sound": boolean, "glow": boolean,
  ///            "colorChange": boolean, "sprayWater": boolean }
  features   Json?
  description String?

  // ---------- 供货与定制 ----------
  supplyModes SupplyMode[] @default([])
  moq         Int?         // 最小起订量（新增，无旧字段来源）
  leadTime    Int?         // 标准交期（天）（新增，无旧字段来源）
  hsCode      String?      // 海关编码（出口必备）（新增，无旧字段来源）
  /// 标准价（唯一标准价来源；客户级标准产品价格见 ProductPrice）
  defaultPrice    Decimal? @db.Decimal(18, 6)
  defaultCurrency Currency @default(USD)
  defaultTaxRate  Decimal? @db.Decimal(9, 4) @default(13)   // 百分数：13 = 13%

  // ---------- 库存（V1 保留冗余字段，见总览 Q2：不引入独立库存域）----------
  stock         Int? @default(0)
  lowStockAlert Int? @default(0)

  // ---------- 可见性与归属 ----------
  visibility ProductVisibility @default(PUBLIC)
  visibleUsers ProductVisibleUser[]
  ownerId    String?
  owner      User?   @relation("ProductOwner", fields: [ownerId], references: [id], onDelete: SetNull)

  // ---------- 关联 ----------
  coverImage       String?               // 主图冗余（列表页免 join）
  certifications   ProductCertification[]
  tasks            ProductTask[]
  combos           ComboItem[]
  customerProducts CustomerProduct[]
  prices           ProductPrice[]
  leadItems        LeadItem[]
  opportunityItems OpportunityItem[]
  quotationItems   QuotationItem[]
  sampleOrders     SampleOrder[]          // SampleOrder.productId 的反向
  salesOrderItems  SalesOrderItem[]       // SalesOrderItem.productId 的反向
  purchaseOrderItems PurchaseOrderItem[]  // PurchaseOrderItem.productId 的反向

  status    MasterStatus @default(ACTIVE)   // 旧库曾在迁移中删除该列，本次属**重新引入**
  createdBy String?
  createdAt DateTime  @default(now())
  updatedBy String?
  updatedAt DateTime  @updatedAt
  deletedAt DateTime?                        // 软删除白名单（Q9）

  @@index([categoryId])
  @@index([audienceId])
  @@index([ownerId])
  @@index([status])
  @@index([name])
  // 如需按颜色筛选：@@index([colors(ops: ArrayOps)], type: Gin)
}
```

> **`features` 的结构校验（应用层）**
>
> ```ts
> const FeatureFlagsSchema = z.object({
>   logo: z.boolean().default(false),
>   sound: z.boolean().default(false),
>   glow: z.boolean().default(false),
>   colorChange: z.boolean().default(false),
>   sprayWater: z.boolean().default(false),
> }).strict()
> ```
>
> - 写入前校验；读取时对 `null` / 缺字段做默认填充；
> - **禁止**在 PostgreSQL 下使用 Prisma `type`（composite type 仅 MongoDB 连接器支持，会导致 `prisma validate` 直接失败）。

### 2.2 相对旧 `SingleProduct` 的字段去向

| 旧字段 | 新去向 | 理由 |
|---|---|---|
| `name` / `sku` | `Product.name` / `Product.sku` | 保留 |
| — | `Product.productNo` | **新增，无旧字段来源**：旧版 `sku` 兼职编号，业务编号与内部编码混用 |
| `crafts`（隐式 M2M） | **显式关联表 `ProductCraftLink`**（物理表名不变） | 见 §3.1；模型改名会使 Prisma 期望的隐式表名与 A/B 列语义变化，风险极高 |
| `sizeL/sizeW/sizeH/weight` | `Float?`（原 `String?`） | 字符串尺寸无法排序、无法算体积重；物理量非金额，允许 `Float` |
| `logo/sound/glow/colorChange/sprayWater` | `features: Json?` | 结构化后前端表单可整体透传；PostgreSQL 不支持 composite type |
| `material` | `Product.material` | **新增，无旧字段来源** |
| — | `Product.moq` / `leadTime` / `hsCode` | **新增，无旧字段来源**（旧库无对应列） |
| `packaging` | `Product.packaging` | **保留**（旧 `SingleProduct.packaging String?`） |
| `sampleNo` | → `ProductTask` | 打样单号属于「任务实例」，不属于产品主数据（P1-6） |
| `progress`（JSON 字符串） | → `ProductTask` 表 | JSON 无法查询「哪些产品卡在开模」 |
| `certificationIds`（逗号串） | → `ProductCertification` 表 | 逗号串无法表达有效期、无法 join |
| `images`（JSON 字符串） | → `Attachment`(ownerType=PRODUCT) + `coverImage` | P0-4 |
| `price/currency/taxRate` | → `defaultPrice`(`Decimal(18,6)`) / `defaultCurrency`(`Currency`) / `defaultTaxRate`(`Decimal(9,4)`) + `ProductPrice` | 标准价保留在 Product，**客户级标准产品价格**独立成表 `ProductPrice`；`defaultCurrency` 由 `String` 改为 `Currency` 枚举 |
| `stock/lowStockAlert` | **V1 暂留** `stock Int?` / `lowStockAlert Int?` | 见总览 Q2：V1 不引入独立库存域，字段保留待后续迁移 |
| `audienceId/categoryId` | 保留，`onDelete` 改为 `SetNull` | 删除品类不应连带删产品 |
| `visibility/visibleUsers` | 保留，枚举化 | — |
| `ownerId`（负责人） | 保留（语义明确为产品负责人） | — |
| `source/remark` | 保留 | — |
| `status` | `MasterStatus @default(ACTIVE)` | **重新引入**：旧库曾在历史迁移中删除该列，本次不是「假设旧字段仍存在」，迁移文档需按「新增列」处理 |
| — | `deletedAt` | **新增**（软删除白名单，Q9） |

### 3.1 `Product` ↔ `ProductCraft` 关联表（**高风险迁移点，ADR-17 定案**）

**旧库真实状态（已核实）**

| 项 | 值 |
|---|---|
| 物理关联表 | `_ProductCraftToSingleProduct` |
| 列 `A` | `ProductCraft.id` |
| 列 `B` | `SingleProduct.id` |
| 主键 | `_ProductCraftToSingleProduct_AB_pkey`（`A, B`） |
| 外键 | `_ProductCraftToSingleProduct_A_fkey` → `ProductCraft`；`_ProductCraftToSingleProduct_B_fkey` → `SingleProduct` |
| 索引 | `_ProductCraftToSingleProduct_B_index`（`B`） |

**风险**：`SingleProduct` 改名 `Product` 后，Prisma 对隐式 M2M 推导的表名变为 `_ProductCraftToProduct`（按**模型名**字典序：`Product` < `ProductCraft`），且 A/B 列语义**翻转**（A 应为 `Product`，B 应为 `ProductCraft`）。

结论：**单纯 `ALTER TABLE ... RENAME` 不够**——即使表名改对，A/B 语义也已反转，会导致产品-工艺关联**静默错乱**；而若只依赖 Prisma 自动 diff，则会 DROP + CREATE 关联表，**清空全部产品-工艺关系**。

**方案对比**

| 方案 | 物理表 | 数据风险 | 业务代码影响 | 结论 |
|---|---|---|---|---|
| **A（采用）显式关联表 `ProductCraftLink` + `@@map("_ProductCraftToSingleProduct")`** | **零变更** | **零搬迁** | `product.crafts` 由 `ProductCraft[]` 变为 `ProductCraftLink[]`（需 1 处适配） | ✅ **V1 采用** |
| B. 保留隐式 M2M，手写 `RENAME` + A/B 内容交换 | 变为 `_ProductCraftToProduct` | 需 `UPDATE ... SET A/B 互换`，出错即静默错乱 | `product.crafts` 不变 | 备选，风险高于 A |
| C. 依赖 `migrate dev` 自动 diff | 被重建 | **清空全部关联** | — | ❌ 禁止 |

**方案 A 的最终定义**

```prisma
/// Product ↔ ProductCraft 关联表。
/// 物理表为旧库已存在的 `_ProductCraftToSingleProduct`，此处用 @@map + @map 精确对齐列语义，
/// 以避免 Product 改名后 Prisma 重建 join table（会清空全部产品-工艺关系）。
/// 注意：A 列 = ProductCraft.id，B 列 = Product(原 SingleProduct).id，与 Prisma 默认推导**相反**，
/// 因此必须显式 @map，且 @@id 字段顺序须与既有主键 (A, B) 一致。
model ProductCraftLink {
  productCraftId String @map("A")
  productId      String @map("B")

  productCraft ProductCraft @relation(fields: [productCraftId], references: [id], onDelete: Cascade)
  product      Product      @relation(fields: [productId], references: [id], onDelete: Cascade)

  @@id([productCraftId, productId])
  @@index([productId])
  @@map("_ProductCraftToSingleProduct")
}
```

**迁移动作（`05` §13 详述）**：**物理表与列零 DDL**（表名、`A`/`B` 列名与语义均不变）。仅需在 `schema.prisma` 中声明上述模型。

> **⚠️ 索引名必须人工处理**：旧库的 2 个索引仍是隐式 M2M 时代的名字 —— `migrations/20260820023856_init/migration.sql` 建的是 `_ProductToProductCraft_AB_unique` / `_ProductToProductCraft_B_index`，而表已由 `20260824000000_split_single_combo` 改名为 `_ProductCraftToSingleProduct`（索引未同步改名）。
> Prisma 依据 `@@map` + 字段名会推导出 `_ProductCraftToSingleProduct_AB_unique` / `_ProductCraftToSingleProduct_B_index`，因此 `prisma migrate diff` **会产生非零 DDL**。
> 处理方式：人工编写 migration，只做索引改名 ——
> ```sql
> ALTER INDEX "_ProductToProductCraft_AB_unique" RENAME TO "_ProductCraftToSingleProduct_AB_unique";
> ALTER INDEX "_ProductToProductCraft_B_index"  RENAME TO "_ProductCraftToSingleProduct_B_index";
> ```
> **禁止**接受自动生成的 `DROP INDEX` + `CREATE INDEX`（会短暂移除 `(A,B)` 唯一约束）。

**表数口径**：`ProductCraftLink` 是**关联表**，物理表在旧库本就存在，**不计入 02 的 13 张业务表**，也不计入「新增 20 张」。因此 `schema.prisma` 的 model 总数为 **51 = 业务表 50 + 关联表 1**。

> **业务代码适配点（后续实施阶段）**：`product.crafts` 的返回结构变为 `{ productCraftId, productCraft }[]`。若需要保持原响应形状，在 service 层做一次 `map(i => i.productCraft)` 即可（**不得**因此改回隐式 M2M）。

## 4. 认证（2 张）

```prisma
/// 认证字典（沿用旧 Certificate）
model Certificate {
  id         String   @id @default(cuid())
  name       String              // CE 认证 / EN71 / ASTM F963
  code       String?  @unique    // CE / FCC / EN71
  issuer     String?
  category   String?             // 安全 / 电磁兼容 / 环保
  validUntil DateTime?           // 字典级默认有效期
  status     MasterStatus @default(ACTIVE)
  logo       String?
  remark     String?
  products   ProductCertification[]
  createdAt  DateTime @default(now())
  updatedAt  DateTime @updatedAt
}

/// 产品-认证关联（替代 Product.certificationIds 逗号串）
model ProductCertification {
  id            String   @id @default(cuid())
  productId     String
  product       Product  @relation(fields: [productId], references: [id], onDelete: Cascade)
  certificateId String
  certificate   Certificate @relation(fields: [certificateId], references: [id], onDelete: Restrict)
  /// 本产品持有的证书编号与有效期（可与字典默认值不同）
  certNo        String?
  issuedAt      DateTime?
  validUntil    DateTime?
  /// 证书文件 → Attachment(ownerType=CERTIFICATE)
  remark        String?
  createdAt     DateTime @default(now())
  updatedAt     DateTime @updatedAt
  @@unique([productId, certificateId])
  @@index([certificateId])
  @@index([validUntil])
}
```

> **为什么要拆**：审计 P1-6 指出 `certificationIds` 用逗号串存 id，导致 ① 无法表达「本产品的证书编号/有效期」；② 证书过期无预警能力（`validUntil` 在 `Certificate` 上，是全局值而非产品实例值）；③ 删除证书时逗号串变脏数据。

## 5. 产品任务（1 张）

```prisma
/// 产品任务/进度：替代旧 Product.progress(JSON) 与 Product.sampleNo
model ProductTask {
  id        String            @id @default(cuid())
  productId String
  product   Product           @relation(fields: [productId], references: [id], onDelete: Cascade)
  type      ProductTaskType
  title     String
  status    ProductTaskStatus @default(PENDING)
  /// 关联的业务单据（打样单 / 报价单），用于把任务串回主链
  refType   String?           // SAMPLE_ORDER / QUOTATION
  refId     String?
  refNo     String?
  ownerId   String?
  dueDate   DateTime?
  sort      Int               @default(0)
  remark    String?
  createdAt DateTime          @default(now())
  updatedAt DateTime          @updatedAt
  @@index([productId, status])
  @@index([refType, refId])
}

/// 旧 progress JSON 形态（审计证据）：
///   { "sample": {"status":"DONE"}, "quote": {"subTask1": true, ...} }
/// 迁移映射见 05 文档 §2.3
```

> `refType` / `refId` 是**任务到单据的软关联**（可为空，不参与权限/统计），因此不使用外键；若某类任务需要硬关联，应在后续版本按其类型拆出专用 FK 字段。

## 6. 组合品（2 张）

```prisma
model ComboProduct {
  id          String   @id @default(cuid())
  comboNo     String   @unique   // CMB-yyyyMMdd-0001（新增，旧版无编号）
  name        String
  sku         String?  @unique
  description String?
  ownerId     String?            // 旧版为必填 String（无外键），改为可空 + 外键
  owner       User?    @relation("ComboOwner", fields: [ownerId], references: [id], onDelete: SetNull)
  status      MasterStatus @default(ACTIVE)   // 停用即「删除」语义（Q9：此处不设 deletedAt）
  remark      String?
  items       ComboItem[]
  createdBy   String?
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt
  @@index([ownerId])
}

model ComboItem {
  id        String   @id @default(cuid())
  comboId   String   @map("groupId")   // 旧列名 groupId，用 @map 保留物理列名
  combo     ComboProduct @relation(fields: [comboId], references: [id], onDelete: Cascade)
  productId String?
  product   Product? @relation(fields: [productId], references: [id], onDelete: Restrict)
  quantity  Int      @default(1)
  price     Decimal? @db.Decimal(18, 6)   // 组合内单价（可空，空则取 Product 默认价）
  sort      Int      @default(0)
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  @@unique([comboId, productId])
  @@index([productId])
}
```

**变更说明**

| 项 | 旧 | 新 | 原因 |
|---|---|---|---|
| `ComboProduct.ownerId` | `String`（必填，外键名 `owner`，语义混作创建人） | `String?` + 真外键 + 独立 `createdBy` | 旧版 `ownerId` 语义歧义（既是负责人又当创建人） |
| `ComboProduct.deletedAt` | draft1 新增 | **删除该字段** | Q9：软删除仅 4 张主数据表；组合品用 `status = INACTIVE` 表达停用 |
| `ComboItem.groupId` | 字段名 `groupId` 指向 `ComboProduct` | 字段名 `comboId`，**物理列用 `@map("groupId")` 保留** | 命名与实际对象不符；用 `@map` 避免 `RENAME COLUMN` 与全量重写 |
| `ComboItem.productId` `onDelete` | `Cascade` | `Restrict` | 删产品不应连带删除组合行（P0-5） |
| `ProductActivity.comboId` | 组合操作记录复用产品日志表（多态可空） | **删除**，组合操作写入 `OperationLog` | 多态可空双外键是反模式，且组合操作频次低 |

**变更说明**：新增编号、软删除、`email/country`、能力标签、账期、评级。旧版仅 6 个字段，无法支撑「按工艺选供应商」这一 OEM 核心动作。

> **`supplierNo` 迁移注意**：`supplierNo` 为 `NOT NULL @unique` 新增列 → 必须先补历史编号（见 `05` §5），并同步 `NumberSequence(code='SUP')` 的 `currentValue`。

## 11. 本层实施注意事项（draft2 补充）

| # | 事项 | 说明 |
|---|---|---|
| 1 | **禁止** `type`（composite type） | PostgreSQL 不支持；`features` 用 `Json?` + Zod |
| 2 | `Float` 仅限物理量 | `sizeL/W/H`、`weight` 可用 `Float`；金额/单价/税率一律 `Decimal`（`defaultPrice` 18,6 / `defaultTaxRate` 9,4） |
| 3 | `SingleProduct → Product` 改名 | 用 `ALTER TABLE "SingleProduct" RENAME TO "Product"`（FK 自动跟随），**禁止**依赖 `migrate dev` 自动 diff；若倾向零 DDL，可改用 `@@map("SingleProduct")`（二选一，见 `05` §13） |
| 4 | `ProductCraftLink` | 表/列**零 DDL**，但索引名不一致会产生 2 条 DDL；必须人工写成 `ALTER INDEX ... RENAME TO ...`，**禁止** `DROP` + `CREATE`（见 §3.1、`05` §13） |
| 5 | `ComboItem.comboId` | 用 `@map("groupId")` 保留物理列名，**不产生 `RENAME COLUMN`** |
| 6 | `Product.status` | 属**重新引入**的列，迁移按「新增列 + 回填 ACTIVE」处理 |
| 7 | 新增字段的来源标注 | `material` / `moq` / `leadTime` / `hsCode` / `productNo` / `deletedAt` 均为**新增，无旧字段来源**；`packaging` **不属新增**，来自旧 `SingleProduct.packaging`（保留）。`05` §2.2 已列明 |
| 8 | 外键补齐 | `Product` 已补 `sampleOrders` / `salesOrderItems` / `purchaseOrderItems`；`Supplier` 已补 `productionOrderItems` |
| 9 | `deletedAt` 仅 4 张表 | 本层只有 `Product` 与 `Supplier` 声明；`ComboProduct` 不得声明 |
| 10 | 索引语法 | 若启用颜色筛选，`@@index([colors(ops: ArrayOps)], type: Gin)`，**不得**写裸 `@@index([colors])` |
